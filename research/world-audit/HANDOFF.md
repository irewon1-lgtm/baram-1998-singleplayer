# 다음 Codex 설치·구현 지시

1. main에 합치지 말고 이 조사 브랜치에서 개발용 별도 브랜치를 만든다. 기존1998 원장과 압축 아카이브는 보존한다. 조사 원장에 기록된 정확한 커밋으로 private 격리 폴더에 소스를 다시 가져오고 `git fsck`와 SHA256을 대조한다.
2. 최우선은 Project1998 `36905428ff59329be28c6a4579e41f4fd9e9a967`. 재배포/수정본 공개를 시작하기 전에 저작자에게 코드 및 데이터의 범위별 라이선스를 받는다. 원작 클라이언트/에셋 권리도 별도로 확인한다. 실제 허가 전 public에는 이 프로젝트의 코드/리소스를 복제하지 않는다.
3. 개인 개발 PC에 무료 .NET8 SDK를 설치한다. 여기서는 Linux SDK8.0.425/Runtime8.0.31로 빌드했다. 아래 명령은 소스 루트에서 실행한다. 유료 설치·외부 서버·운영 배포가 필요하지 않다.

```sh
dotnet build Project1998.Server.slnf --nologo --disable-build-servers -m:1 -p:BuildInParallel=false -p:UseSharedCompilation=false -nr:false
dotnet Server/bin/Debug/net8.0/Server.dll --selftest
python /path/to/this-repo/tools/run_local_server_probe.py --help
```

프로브는 `--source`, `--dotnet`, `--state`, `--logs`를 요구한다. 독립 상태 폴더를 지정한다. 주소는127.0.0.1, 로그인3100/3101·게임3105/3106을 사용하며 점유된 포트면 중단한다. 테스트 후 자체 시작한 프로세스만 종료한다. 같은 상태로 다시 실행하여 저장 재접속을 확인한다. DB를 공개 저장소에 넣지 않는다.

4. Windows 격리 VM에서 원장 SHA256과 일치하는4.95 설치파일을 최신 AV와 실행 전 정적검사 후 설치한다. 현재 연구에서 설치파일만 확보했고 Wise 전체 압축 해제는 완료하지 못했다. 설치된 EXE/DAT/맵 파일의 해시를 원장에 추가한다. loopback 접속 설정/클라이언트 패치가 필요하다면 원본을 보존하고 개인 로컬 사본에만 적용한다. 현 소스의 버전별 핸드셰이크/맵 인코딩을 실제 클라이언트 패킷으로 검사한다. 원래4.95와 수정을 거친4.95를 구분한다.
5. 소스와 DB 기본 시험을 반복한 후 실제 화면에서 로그인→캐릭터 생성→이동/충돌/맵 전환→몬스터 공격→경험치/레벨→아이템 획득/장비→마법/MP→NPC/상점/퀘스트→종료/재접속 순으로 수행한다. 화면/프로브 로그/DB 변경/exit code를 보관하고 수행한 항목만 PASS로 기록한다. 현재 전체 xUnit은 러너 오류/직접 러너 비정상 종료로 미통과이므로 정상 Windows/.NET 환경에서 다시 실행한다.
6. 에뮬레이터를 활용할 수 없으면 독자 클라이언트+독자 오프라인 런타임 경로로 전환한다. 코드 재사용 우선순위는 MIT TKMapper·Godot EPFViewer의 형식 읽기·팔레트·맵 편집 부분이다. 타일 인덱스/맵 레코드는 P1998 형식과 차이가 있어 어댑터가 필요하다. GPL TKClassic/ServTK를 가져오려면 GPL 배포 의무에 맞는 구성을 선택한다. 무라이선스 구현은 참고 사실과 독자 구현을 분리한다.
7. 자체 구현 필요 사항: 1998/1999/2000/2001·KR/NA 버전 프로필, 타일/충돌/워프, 애니메이션 렌더링, 입력/UI/한글, 전투/AI/드롭/경험치, 마법/퀘스트/NPC, 독립 SQLite 저장/백업, 루프백 네트워크 또는 직접 런타임 연결, 자료 출처와 권리 메타데이터. 자료가 없는 규칙은 추정임을 표시하고 후대 RTK 값으로 원본을 덮지 않는다.
8. 원본4.03은 실제613맵과106 EPF를 제공하므로 파일 형식/시대 비교에 즉시 활용할 수 있다. 한국4.91은133 EPF/PAL36의 독립 프로필. own `tools/inspect_legacy_dat.py`로 원본을 읽고 메타데이터만 출력한다. 그래픽 렌더링과 몬스터/아이템 의미 매핑은 추가 검증해야 한다. 각 게임 자료는 개인 폴더 외부에서 public 번들로 패키징하지 않는다.

NemuTK에 대한 새 다운로드 링크/재배포 허가를 확보하기 전 그 구현을 개발 기반으로 선택하지 않는다. Java RTK는 JDK25와 별도 libGDX 클라이언트를 요구하고 retail protocol과 달라4.95 목표의 지름길이 아니다. CoM2014는 참고용 후대 Mithia 데이터로 다룬다.
