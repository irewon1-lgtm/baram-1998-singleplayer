## 0. 최종 목적을 고정하고 이번 작업부터 실행하라

한국판 1998~2001년 바람의나라의 경험을 최대한 충실하게 재현한 개인용 싱글플레이 게임을 처음부터 다시 구축한다. 새로 만드는 것은 게임의 구조이며, 원본 자료와 검증된 도구·재사용 가능한 부품까지 버리는 것이 아니다.

Windows와 Android 휴대폰·Galaxy Tab S10 FE에서 같은 규칙·콘텐츠·저장 형식을 사용한다. 오프라인 플레이와 같은 계정·같은 캐릭터의 기기 간 순차 이어하기를 유지한다. 사용자가 보낸 사진을 기준으로 오른쪽 물품/기술/장비/능력치 전환, 아래 상태창 유지, 실제 아이콘·착용 외형·한국어 표시를 구현할 계획이다.

전체 순서는 바꾸지 마라.
P0/P1 자료 확보·정리 → P2 위험 기술 검증 → P3 로그인·생성부터 저장·재진입까지 실제 한 구간 → P4 전체 자료 일괄 반영 → P5 전체 시스템·콘텐츠 → P6 이어하기·업데이트 → P7 종합 플레이 검증.

이번에는 P0/P1을 실제 수행하고 결과를 저장하라. 계획을 다시 설명하는 것으로 끝내지 마라. 새 게임 코드 작성, 기존 게임 수정, 기준 서버 실행, APK/EXE 빌드, 배포는 이번 범위가 아니다. 목록화·정적 해독·중복/참조 검사에 필요한 작은 스크립트와 기존 도구의 안전한 자료 처리는 허용한다.

이번 지시문을 전달받아 실제 작업을 시작한 사실과 P0/P1 범위만 STATE.json에 기록하라. 계획·범위를 임의로 축소하거나 엔진·연도·UI를 바꾸지 마라. 충돌은 기록하고, 충돌하지 않는 작업은 계속하라.

기존 추출 결과는 입력 해시·파서 버전·검증 범위가 맞으면 재사용하라. 전부 다시 해독하거나 기존 게임 전체를 다시 감사하지 마라. 손상·해독 실패·인코딩 오류·접근 차단·미조사는 각각 구분하라. 파일명이나 과거 보고서의 개수만으로 확보·정확성·활용 완료를 선언하지 마라.

## 3. 로그인부터 종료까지 '요구사항–자료–기능–시험 연결표'를 만들어라

이번 핵심 산출물은 자료 링크 모음이 아니라 이 연결표다. 적어도 다음 범위를 빠짐없이 다뤄라.

- 시작: 타이틀, 로딩, 아이디/로컬 프로필, 실제 계정 인증, 캐릭터 생성·선택, 한글 입력·중복·오류·취소, 게임 진입.
- 화면: 오른쪽 네 패널, 능력치, 물품 아이콘, 착용 외형, 대화·메시지, PC/폰/태블릿 입력과 배치.
- 세계: 한국 지도 지형·충돌·가림·출구, 마을/사냥터 연결, NPC 위치, 몬스터 종·변종·배치·리스폰, 미니맵·지역명.
- 성장·전투: 평민 Lv1, Lv5 전직, 네 직업 학습 조건·기술·버프, 1~99·승급, 일반 공격·피격·드롭·획득, 죽음·부활·귀환.
- 생활: NPC별 대화·재고·구매·판매·수리·제작, 장착·해제·내구도, 퀘스트와 진행 조건.
- 시청각: 캐릭터/장비 네 방향, 프레임·지연·기준점·팔레트·레이어, 기술 효과·투사체, 효과음/BGM, 입력부터 명중·소리·다음 행동까지의 시간축.
- 보존·운영: 저장·재시작, 오프라인, 동일 계정 PC→Android→PC 이어하기, 오래된 저장·충돌·업데이트·이전·복구, 로딩·메모리·입력 성능.

각 요구사항에 안정적인 requirement_id를 부여하고, 기대 동작, 정본 항목, 필요한 근거, 실제 source_id와 파일/인덱스/문서 위치/영상 타임코드, 확인된 정보, 부족한 정보, 필요한 구현 기능, 정상·실패·취소 시험, 우선순위와 예정 단계를 연결하라.

'기술 전체', '지도 전체' 한 줄로 뭉개지 말고 자료·실패 원인이 달라지는 단위로 나눠라. 반대로 이 단계에서 모든 아이템의 모든 수치를 완성해야 다음으로 갈 수 있다는 조건을 만들지 마라.

옛 로그인 화면, 오프라인 프로필, 실제 서버 인증·기기 연동은 서로 다른 행으로 관리하라. 원본 화면 복원에 필요한 자료와 새 편의 기능의 설계 요구도 구분하라.

README만 읽고 끝내지 말고 실제 소스·데이터·문서에서 어떤 요구사항을 해결할 수 있는지 확인하라. 로그인/캐릭터/저장, 지도·출구·스폰, 직업 기술·학습, 상점·드롭, 그림·소리의 실제 파일 경로와 버전을 기록하라. 자료 사본을 확보하면 커밋/해시를 고정하되 이 단계에서 새 게임에 포팅하지 마라.

포크·재게시물의 같은 내용을 여러 독립 근거로 세지 마라. 처음 발견한 후보는 넓게 확인하되 이후에는 미해결 요구사항을 메울 자료에 우선순위를 두고, 이미 처리한 입력을 반복 수집하지 마라.

어려운 항목은 별도 추적하라. 기술 모양은 프레임·순서·시간·레이어·효과 ID, 사운드는 파일·소리 ID·호출 조건·재생 시점, 캐릭터 생성은 선택 순서·외형 조합·오류 상태를 찾아 연결하라. 영상은 버전·FPS·속도·타임코드를 기록하고 사진 한 장으로 타격 타이밍을 확정하지 마라.

공개 설명에서 '지원한다'는 주장과 직접 확보한 코드, 실제 실행 확인을 구분하라. 실행 가능한 기준본 후보에는 클라이언트/서버 버전 조합·필요 파일·설정·의존성·아직 모르는 조건을 기록하라. '로그인부터 한국판 전체를 완성한 자료'를 확보했다고 과장하지 마라.

## 5. 충돌·미활용을 분류하고 하나의 복원 프로필 초안을 제안하라

원본 / 추출본 / 채택 후보 / 실행 패키지를 구분하라. 지금은 후보를 만드는 단계이며 실행 패키지가 만들어졌다고 표시하지 마라. 처음부터 별도 웹서비스·벡터 DB·복잡한 관리 시스템을 만들지 말고 기존 도구와 경량 파일 색인을 재사용하라.

동일 이름이라도 한국/북미, 연도, 직업, 일반종/변종/보스가 다르면 별도 후보로 관리하라. 원본 숫자 ID는 지역·버전과 함께 식별하고 한국어 이름을 고유 ID로 쓰지 마라. 팔레트 차이를 잘못된 중복으로 삭제하지 마라.

출처는 아이템 하나 전체가 아니라 그림·가격·착용 조건 등 필드별로 연결하라. 다른 시대·지역의 값을 무조건 평균 내지 마라. 클라이언트에 그림이 있다는 이유로 서버의 배치·경험치·확률까지 확정하지 마라.

기본 도시·직업·성장·UI가 일관된 기본 복원 프로필 초안을 제시하라. 한국 1998~2001 범위 안에서 근거를 비교하고, 확인되지 않은 연도는 PROVISIONAL로 남겨라. 사용자 사진의 화면 요구는 보존하되 촬영 연도 확인과 구분하라. 근거 없는 범위 축소·후대 콘텐츠 혼합은 하지 마라.

세 가지 판정 축은 정본대로 분리한다.
- 사실성: ORIGINAL_VERIFIED / CORROBORATED_RECONSTRUCTION / INFERRED / UNKNOWN.
- 이용 상태: DISCOVERED / ACQUIRED / DECODED / IDENTIFIED / BOUND / EXERCISED.
- 시험: PASS / FAIL / NOT_RUN / BLOCKED. README의 설명은 DOCUMENTED_CLAIM이다.

새 게임이 아직 없으므로 기존 게임의 실행 결과를 새 게임의 BOUND/EXERCISED로 옮기지 마라.

미활용 이유마다 다음 해결 작업을 붙여라: 접근 불가, 해독 실패, 의미/ID 미식별, 버전 불일치, 지원 코드 없음, 기존 패키징/캐시 연결 결함, 의도적 미사용. '자료는 있는데 안 됨'으로 끝내지 마라.

끝내 자료가 없는 것은 대응 확인된 판본이나 원본 조합으로 보완할 방법과 확인 시험을 제안하라. 이번 단계에서 대체 몬스터·지도·효과를 생성해 원본 빈칸을 감추지 마라.

## 6. 기존 실패를 새 게임의 시험 요구사항으로 계승하라

다음 결함을 연결표에 각각 등록하고, 방지 조건과 독립 비교 근거를 붙여라.

1. Lv1 직업/미학습 기술, 전직·직업별 학습 제한의 퇴행.
2. 북미 지형에 한국 이름만 붙이거나 임시 포털로 정상 지형 연결을 대신하는 문제.
3. 비영사천문의 village 고정 및 귀환·효과 반복에서 발생하는 멈춤.
4. 초보 사냥터의 변종/보스 혼입, 입구 주변 추정 스폰을 원작 배치로 오인하는 문제.
5. 모든 상점에 공통 재고·수리·제작 서비스를 붙이는 문제.
6. 아이콘 참조는 있지만 안 그리거나 다른 목도 이미지로 대체하는 문제.
7. 지도 갱신 시 캐릭터·바닥 전리품을 입구로 옮기거나 잃는 문제.
8. 필수 지도 누락 무시와 변환 코드 변경 후 오래된 캐시 재사용.
9. 좌우 방향·착용 레이어·터치 좌표 오류와 UI 수정에 따른 게임 규칙 퇴행.
10. 파일 전달을 계정 동기화로, Linux/에뮬레이터 시험을 실제 Windows/Galaxy 시험으로 보고하는 문제.

이것은 시험 설계다. 실행하지 않은 새 게임 시험을 PASS로 기재하지 마라.

## 7. 실제 산출물과 중단 후 재개 지점을 저장하라

계획 브랜치의 최신 상태를 보존하며 아래 위치에 저장하라. 같은 목적의 결과가 이미 있으면 새 보고서를 복제하지 말고 이어서 갱신하라.

- docs/rebuild/step01/REPORT.md: 고정 목표·읽은 계획 버전, 조사 범위, 실제 발견/확보/해독 범위, 기본 복원 프로필 초안, 우선 결함과 결론.
- docs/rebuild/step01/requirements.csv: 요구사항–자료–기능–시험 연결표.
- docs/rebuild/step01/sources.jsonl: 원본·외부 자료 목록, 실제 위치·해시·버전·출처 계보·활용 상태. 큰 압축 내부 목록은 별도 파일로 분리해 참조해도 된다.
- docs/rebuild/step01/issues.csv: 충돌·부족·오류·미활용 항목, 연결 ID·이유·해결 방법·중요도·다음 작업. P2 필수 장애와 후속 콘텐츠 보완을 구분하라.
- docs/rebuild/step01/NEXT_P2.md: Codex에 인계할 기술검증 단위, 실제 입력 위치·버전·해시, 검증 도구, 독립 기대 결과, 준비된 것/막힌 것.
- docs/rebuild/STATE.json: 완료한 작업, 미실행 작업, 입력 지문, 저장된 증거, 차단 원인, 정확한 다음 재개 지점.

작은 검사 스크립트가 필요하면 tools/rebuild/step01/에 분리하라. 원본 바이트·실제 세이브·비밀번호·토큰·서명키는 공개 저장소에 올리지 마라. 원본은 기존 개인 보관 위치에 유지하고 재사용 가능한 접근 경로와 해시를 남겨라. 임시 작업 경로만 써 놓고 다른 작업자가 접근 가능하다고 단정하지 마라.

ID 중복·깨진 참조·출처 없는 확정값·해시 누락·필수 범주 누락을 실제 검사하고 그 결과만 기록하라. 의미 있는 묶음마다 커밋·원격 재조회로 저장을 확인하라. STATE를 갱신하기 전 다시 읽고 다른 작업자의 변경을 덮어쓰지 마라. 게임 미구현 상태는 그대로 유지한다.

연결이 끊기면 원격 결과와 STATE에서 이어가라. 동일 입력 재조사, 전체 감사 재시작, 같은 실패의 무한 재시도는 하지 마라. 접근 불가능한 자료 한 묶음 때문에 가능한 나머지 작업까지 멈추지 마라.

## 8. 이번 단계의 완료 기준과 최종 보고

사이트 개수나 파일 개수가 아니라, 필수 기능마다 쓸 자료·부족한 근거·필요한 구현·확인할 시험이 연결돼야 한다. 접근 가능한 기존 자료는 목록화하고 미조사 범위도 남겨야 한다. 기술 이펙트·타격감·소리·아이디/캐릭터 생성의 어려운 항목도 빠뜨리지 마라.

인터넷 모든 자료를 다 찾거나 모든 미확인을 해결할 때까지 P1을 끝내지 않는 방식은 금지한다. P2에서 확인할 한국 맵·캐릭터 합성·효과/소리·로그인/생성·두 플랫폼 입력/저장 후보의 입력 묶음과 검증 방법을 준비하고, 남은 보완 목록을 분리하면 이번 작업을 마무리하라. 필수 입력이 없으면 해당 P2 시험만 차단으로 표시하라.

마지막에는 다음을 보고하라.
- 실제 수행 범위와 접근/조사하지 못한 범위.
- 다섯 질문 Q1~Q5에 대응하는 산출물 위치.
- 새로 확보한 자료가 어떤 빈칸을 해결했는지.
- 재사용 가능한 후보와 미활용 원인·해결 작업.
- P2 준비/부분 준비/차단 판정, 구체적인 장애와 다음 우선순위.
- 저장 브랜치·커밋·증거와 다운로드 가능한 인계 자료.

전체 게임 완성, 원작 동일, 네이티브 실행 PASS는 이번 결과로 선언하지 마라. 무료 범위만 진행하고 비용 발생 작업은 해당 부분만 중단·보고하라. 기존 브랜치 강제 덮어쓰기·main 병합·기존 파일 교체·배포는 금지한다.

이번 작업을 마치면 P0/P1 결과와 Codex용 P2 인계 준비까지 보고하고, P2 실행이나 새 게임 개발로 임의 진입하지 마라.
