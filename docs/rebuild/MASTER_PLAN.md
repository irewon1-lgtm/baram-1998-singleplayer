사용자 결정: 구할 수 있는 자료는 최대한 구해서 구현한다. 현실적으로 어렵다면 재구성한다. 옛 바람의나라 특정 버전과 정확히 일치할 필요는 없다. 기존 데이터로 복구되지 않으면 기존 데이터 근거, 최신 바람의나라 자료, 타 게임 자료, 마지막으로 근거를 기록한 추론을 사용해 구현한다.

폐지하는 완료 조건: 특정 연도/판본 완전 일치, 원본 셀/서버 ID를 알아야만 재구성 지도 구현 가능, 정확한 마스크/효과/확률이 없으면 기능 구현 영구 유보.
유지하는 완료 조건: 기능이 실제 작동할 것, 규칙과 수치가 일관될 것, 각 콘텐츠에 정상 획득·사용 경로가 있을 것, 최종 파일을 해당 플랫폼에서 검증할 것, 기존 저장을 손상시키지 않을 것, 없는 증거를 PASS로 만들지 않을 것.

## 2. 자료 선택 순서와 중단 없는 보완

각 필드/행동/자산별 적용 순서는 다음과 같다.

| 순위 | 분류 | 적용 |
|---|---|---|
| 1 | LEGACY_VERIFIED | 이미 확보했거나 현실적으로 확보 가능한 기존 한국 자료를 우선 활용 |
| 2 | LEGACY_RECONSTRUCTED | 기존 지도·그림·설명·관련 수치로 조합·보간·재구성 |
| 3 | MODERN_BARAM_ADAPTED | 최신/후대 한국 바람의나라 자료를 현재 4직업·성장·경제에 맞춰 적용 |
| 4 | OTHER_GAME_ADAPTED | 적합한 타 게임의 공개 규칙/데이터를 참고·차용하고 수치·세계관을 맞춤 |
| 5 | INFERRED | 앞선 근거로 정의가 안 되면 설계 이유·제약·시험을 갖춘 추론 구현 |

'자료가 있다'는 URL/파일명만 안다는 뜻이 아니다. 접근·사용 가능하고 해당 기능에 적용할 수 있어야 한다. 조회 시점과 버전을 기록한다. 최신 공식 직업/기술연마 가이드 같은 후보 경로는 확인됐지만 전체 수치·맵·자산이 충분히 제공된다는 보장은 없다. 공개 자료 열람과 원본 자산 재배포는 구분한다. 접근 제한 우회나 사용 가능한 것으로 확인되지 않은 타 게임 자산 무단 패키징 대신 해당 규칙을 참고한 자체 구현을 사용한다.

처음 한 번 기존 전체 인벤토리와 공개 후보 출처를 넓게 대조하고, 이후에는 결손 그룹별 증분 조사만 한다. 178기술을 178번 독립 검색하지 말고 같은 기술군/원본/표/실행 명령 단위로 처리한다. 이미 확보된 정상 자료는 추가 조사 없이 연결한다.

현재 세대의 조사 종료 규칙: 같은 결손 그룹에서 서로 다른 방법으로 2회 진행해도 구현 가능한 새 근거가 없으면 그 경로를 계속 반복하지 않고 다음 보완 단계로 간다. 이는 사이트 두 개만 보거나 자료 수집 전체를 포기하라는 상한이 아니다. 조사 방법/입력/차단 원인을 남기고 새로운 접근·근거가 생기면 다음 자료 세대로 다시 검토한다. 금전·권한·환경 조건 때문에 현실적으로 불가하면 그 사유를 즉시 기록한다.

채택 기록 최소 필드: content_id, field, source_tier, source_ref, observed_version/date, rationale, selected_value/asset, action_type, dependencies, runtime_ref, evidence, status. 기존 JSON/CSV를 확장하고 별도 DB/서비스를 늘리지 않는다. 역사적 미확정은 기록하되 게임 화면을 경고문으로 채우지 않는다.

## 3. 무한 확장과 더미 구현 방지

B2에서 이번 완성 세대 G1의 고유 ID 집합을 동결한다. 대상은 기존 보유 자료 중 선택한 게임에 적합한 콘텐츠와 필수 기능의 결손이다. 중복·타 판본 변형·충돌은 이유를 기록해 합치거나 변형으로 관리한다. G1 이후 새로 발견한 콘텐츠는 다음 세대 후보이며 이미 끝낸 개발을 처음부터 다시 열지 않는다. 치명적 오류·저장 문제는 즉시 수정한다.

자료 없음 때문에 G1 필수 기능을 조용히 삭제하지 않는다. 다섯 단계 보완 후에도 구현 실패면 CODE_FAIL로 남겨 해결한다. 권한/환경 차단과 역사적 자료 공백을 혼동하지 않는다. 원작 미확정 기능도 재구성 구현·기능 시험이 통과하면 기능완료가 가능하다.

연결 완료는 이름/ID 등록이 아니다. 아이템은 정상 구매/드롭/퀘스트 중 획득 경로와 사용/착용 기능, 기술은 직업·레벨·재료 조건과 실제 행동, NPC는 접근·대화·서비스, 지도는 출구·충돌·사냥/NPC 연결이 있어야 한다. 유효하지 않은 참조나 지원하지 않는 action_type은 임의 공통 기술로 대체하지 않고 변환 오류로 잡는다. 공통 기술은 공유 가능하지만 고유 기술을 모두 같은 피해/회복으로 위장하지 않는다.

## 4. 실제 실행한 계획 시뮬레이션과 해석

`tools/rebuild/simulate_plan.py`와 `docs/rebuild/PLAN_SIMULATION.json`이 재현 가능한 실행 코드와 결과다. 모델은 자료 접근성·대체 경로·코드 및 시험 상태·Android/Windows 환경의 조합을 열거하고, 의존성 순서와 실패·재개 규칙을 시험한다.

비교 정책: 정확한 원본을 모두 기다림 / 즉시 전부 추론 / 자료 보완은 하되 기기 차단을 전체 작업에 전파 / 자료 보완+의존성 기반 진행+플랫폼별 전달 조건 분리. 마지막 정책을 채택한다. 기기 문제를 초기에 진단하지만 무료 환경이 없으면 해당 검증만 차단하고 독립 콘텐츠 작업을 진행한다.

이는 실제 게임·APK·Windows·원본 지도 복구 시험이 아니다. 가정한 상태에서 규칙의 반례를 찾는 모델이다. 실제 시간·토큰 절감률·게임 완성률·전역 최적성을 입증하지 않는다. 모델의 PASS는 모델에만 적용한다. 실작업의 새 실패를 모델 사례와 실제 회귀시험에 추가한다.

## 6. 핵심 재구성의 적용 방법

지도: 확보한 한국 지도/그림을 기준점으로 성문·궁궐·길드·상점·사냥터 상대 위치를 설계한다. 셀 대응이 안 되면 현 엔진에 맞는 지형/충돌/출구를 재구성한다. 지도·NPC·스폰은 안정 ID로 참조하고 버전별 좌표 변환을 분리한다. 그래픽 일부만 남은 경우에도 원본 입증을 기다리며 기하 구현을 멈추지 않는다.

직업/기술: 확인된 조건은 사용하고 빈 효과/수치만 보완한다. 현대판/타 게임 수치는 그대로 섞지 말고 현재 레벨·체력·마력·피해·사냥시간·경제 규모에 맞춰 환산한다. 환산 공식/설계값을 데이터에 남긴다. 서로 다른 직업의 고유 기능을 구분한다. 조건/소모/대상/판정/효과/소리/종료/저장으로 이어지는 실제 사건을 검사한다.

아이템/NPC: 가능한 원본 아이콘/외형을 재사용하고 미해독 자산은 재구성하여 연결한다. 상점 역할에 맞는 재고를 유지하며 똑같은 전체재고를 공통 기본값으로 사용하지 않는다. 반복되는 그림이 실제 동일 원본인지 더미 대체인지 구분한다.

성장/경제: 기존 목표 4직업·1~99 및 선정 승급을 유지한다. 잠정 XP·드롭·가격·수리비·기술 비용은 통일된 모델로 두고 사냥→전리품→판매→장비/학습→다음 지역이 막히지 않는지 시뮬레이션한다. 자연 테스트에는 돈/XP/재료 직접 지급을 숨기지 않는다. 모든 직업의 장시간 1~99를 실제로 하지 않았다면 전부 완주했다고 하지 않는다.

## 7. 테스트·저장·성능·기기

논리/콘텐츠 자동검사, 시각/음향 관측, 실제 OS 입력, 플랫폼 설치·실행을 분리한다. Linux에서 Windows 내장 PCK 실행은 Windows 실행이 아니다. OS 문자열 주입은 한글 IME 조합 검증이 아니다. 모델에서 platform_available=true는 실제 기기 확보가 아니다.

저장 변경은 원본 사본 보존→안정ID/스키마·좌표 변환→검증→후보 승격이다. 검증 실패/충돌 시 옛 저장을 유지한다. 새 지형에 임의로 입구 좌표를 덮어쓰지 않는다. 현재 시험 패키지·서명·저장 경로를 DELIVERY로 확인하고 후속 보수마다 새 앱ID를 남발하지 않는다. 기존 다른 패키지의 저장 자동 이전은 별도 확인 전 완료로 쓰지 않는다.

같은 계정 Windows→Android→Windows 순차 이어하기 요구는 유지한다. 파일복사를 인증 동기화로 표시하지 않는다. 무료 연결 기반이 없으면 실제 연동만 BLOCKED이며 오프라인 게임은 진행한다. 클라우드 기반 추가가 오프라인 플레이의 필수조건이 되어서는 안 된다.

성능 기준은 목표치와 실제값을 구분한다. 목표는 대응 기기의 안정적인 30FPS 이상 체감이며, 프레임 시간 p95/p99·입력→화면·시작/지도전환·메모리 증가를 기록한다. B1 사용 가능 기기에서 기준을 세우고 동일 기기·장면에서 전후 비교한다. p99를 평균FPS로 숨기지 않고 에뮬레이터 수치를 Galaxy 실기기 성능으로 대체하지 않는다. 현재 호스트 p99 약124ms 기록은 과거 관측으로 보존한다.

## 8. 반복·토큰 낭비 차단

Work 작업 변경 원칙 3개를 고정한다.
1. 현재 기준을 하나로 맞춘다: 이번 범위·실제 코드·STATE.next_action이 일치해야 한다. P3만 수리하면서 전체 구현이라고 보고하지 않는다.
2. 기반과 자료 연결을 나눠 끝낸다: 데이터/저장/월드 계약·실행기를 먼저 정리하고 묶음으로 연결한다. 한 맵/한 기술마다 같은 장시간 자연육성을 반복하지 않는다.
3. 같은 실패를 같은 조건으로 반복하지 않는다: source/code/config/environment/test_scope 지문과 실패 원인·다음 변경을 기록한다.

결정적 같은 실패는 즉시 방법을 바꾼다. 일시적 네트워크/환경 실패는 최대 2회의 동일조건 실패 후 중단하고 방법 변경 또는 해당 범위 BLOCKED로 옮긴다. 입력·가설·관측·환경 변경 없는 재시도는 금지한다. 새 근거가 있으면 새 지문으로 재시험한다. 전체 작업 중단과 개별 차단을 구별한다.

같은 지문의 실제 PASS는 REUSED로 활용한다. 코드/설정/환경/검사범위 중 하나라도 바뀌면 영향검사를 다시 한다. 파일·문서·커밋 수를 성과로 삼지 않는다. 매 결과는 신규 기능/연결 ID, 재현 결함 해결, 원인 입증/배제, 남은 실차단 중 무엇이 바뀌었는지 말한다. 실제 토큰 계측 자료가 없으면 비용/절감률을 추정해 보고하지 않는다.

## 9. 완료 상태와 단일 진행 원장

자료 채택 상태, 구현/시험 상태, 플랫폼 상태는 분리한다. 기능 시험 결과는 PASS/FAIL/NOT_RUN/BLOCKED이며, 재구성은 출처 분류이지 FAIL이 아니다. READY_TO_IMPLEMENT는 구현완료가 아니다. 기존 원본정확성 BLOCKED를 RECONSTRUCTION_QUEUED로 바꿀 수는 있지만 FIXED로 바꾸려면 실제 구현/시험이 필요하다.

STATE에 각 단계·현재 행동·baseline/source/content 지문·실행증거·미해결 이유를 기록한다. 기존22결함은 ID를 유지하고 현대 고증 규칙에 맞는 재구성 처리 대상으로 재분류한다. 추가 결함은 이어 붙이고 과거 실패를 지우지 않는다. G1 집합 분모, 등록, 정상 도달/행동, 표본 시각검증, 실제 플랫폼 검증 수량을 각각 계산한다.

완료를 세 층으로 보고한다: 기능/콘텐츠 세대 완료, 플랫폼별 후보/실사용 확인, 전체 플랫폼·저장연동 목표 완료. 한 층의 성공으로 다른 층을 PASS 처리하지 않는다. 재구성한 대사 하나가 정확한 원문이 아니라고 전체완료를 막지는 않는다.

## 10. 실행 권한·보존·재개

사용자는 이 목표·순서와 Work 운영 변경을 승인했다. 후속 Work는 각 단계 종료 조건을 충족하면 다음 단계로 계속 진행하며, 과거 P3 제한 때문에 P4/P5를 재승인 대기로 돌리지 않는다. 이 문서 고정 세션에서는 문서/모델 코드만 작성하며 앱 수정·실행·빌드·인증 연결은 새 완료로 기록하지 않는다.

현재 작업 브랜치에 문서/모델을 하나의 원자 커밋으로 반영한다. 커밋 직전 HEAD를 확인하고 예상 SHA와 다르면 최신 변경을 읽어 조정하며 force-push하지 않는다. main·다른 브랜치·원본 자산·키·기존 앱·사용자 저장을 변경하지 않는다. 유료 인프라/서비스/계정 자동 생성, 비용 미확인 외부실행, 운영 공개 배포는 별도 승인 없이는 하지 않는다.

중단 시 STATE.next_action·마지막 성공 지문·실패 서명·관련 파일을 저장한다. 재개 시 그 지점부터 시작한다. 전체 자료 조사·SDK 설치·파서 재작성·기존 장시간 플레이를 처음부터 반복하지 않는다. 라이브러리 파일은 실제 바이트 접근을 확인하고 목록만으로 복원 성공이라 하지 않는다.

## 11. 다음 Work의 첫 작업

B1에서 이전 정상 Android 후보와 현재 보수 APK의 실파일·해시·실행환경을 먼저 확인하고 동일 환경 비교로 화면 실패를 좁힌다. 실제 Windows 실행 경로·저장 사본·서명 재사용 가능성도 확인한다. 비용/기기 부재가 확인되면 동일 실패를 반복하지 말고 그 플랫폼 상태와 필요한 자원만 기록한 뒤 B2의 기존 자료 연결 준비로 진행한다. 원본 국내성 셀 대응을 기다리는 과거 제한은 적용하지 않는다.
