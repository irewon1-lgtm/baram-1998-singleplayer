# P0/P1 요구사항 초안 작성 메모

작업: BARAM_REBUILD_P0P1_001 / 계획 BARAM_REBUILD_PLAN_V1_20261015 v1.0.

`requirements.draft.csv`는 통합 담당이 실제 `sources.jsonl`의 source_id를 연결하고 정적 참조 검사를 한 뒤 정본 `requirements.csv`로 확정할 입력이다. 이 파일만으로 자료 확보·원작 고증·게임 작동을 완료 판정하지 않는다. 새 게임 코드, 기준 서버, APK/EXE, 배포와 모든 새 게임 시험은 수행하지 않았다.

## 실제 읽은 입력

- `AGENTS.md` 전체.
- `docs/rebuild/MASTER_PLAN.md` 전체(분할 읽기 포함).
- `docs/rebuild/STATE.json` 전체(동시 작업 중 갱신되는 상태 자료).
- `docs/rebuild/STEP01_WORK_INSTRUCTIONS.md` 전체.
- 비공개 입력 `private-inputs/어플/baram-ui-map-audit-20261015.md` 전체.
- 비공개 입력 `private-inputs/7480.jpg`, `7478.jpg`, `7476.jpg`를 이미지 도구로 직접 표시해 확인.

사진의 큰 화면에서 각각 기술 목록, 물품 목록, 장비 목록·캐릭터 미리보기를 확인했다. 세 사진 모두 필드와 별도인 오른쪽 아래 상태 영역 및 하단 메시지 창을 보인다. 사진은 모바일 브라우저에서 검색 결과를 촬영한 자료이며 사진의 촬영일·원래 게임 버전·1998~2001 일치 여부는 미확인이다. 사진에 있는 특정 상위 기술·장비·수치를 평민 Lv1 기본 지급이나 당시 전체 밸런스의 근거로 삼지 않는다. 네 번째 능력치 탭과 개별 아이콘 등은 사용자 지정 요구와 실제 사진에서 관찰한 사실을 구별한다.

감사 문서의 기존 613/678 아이템·423 지도·고체력 변종·아이콘 fallback·터치 포털 누락 등은 과거 설치본을 조사한 문서의 확인 내용이다. 이번 작성자가 APK·코드·세이브를 새로 실행/재감사했다는 의미가 아니며 새 게임의 BOUND/EXERCISED나 고증 수치로 승계하지 않는다.

공식 한국 연혁 `https://baram.nexon.com/GameGuide/View/3`는 통합 담당이 직접 읽어 전달한 source 후보 `WEB-KR-004`다. 작성자는 이 웹 페이지를 독립 재조회하지 않았다. 통합 담당의 실제 읽기 근거와 sources 레코드가 정본이며 다음 경계만 초안에 반영했다: 3차승급 2000.4, 조합 2000.7, 4차승급 2002.12, 그래픽 리뉴얼 2003.12, 미니맵 2004.6. 미니맵을 1998~2001 원본 기본 기능이라고 요구하지 않고 사용자 편의 후보로 분리했다. 승급·조합은 세부 연도에 맞춘 활성화가 필요하다. KR4.91 ZIP에 들어 있는 문서의 연대는 ZIP 버전과 같다고 확정하지 않는다.

## 초안 구조와 상태 의미

- 120개 요구사항 RQ-001~RQ-120, 범주 9개.
- START 13, UI 13, WORLD 17, GROWTH 13, COMBAT 11, LIFE 13, AV 17, SAVE 13, OPS 10.
- 각 행에 기대 동작·필요 근거·실제 읽은 위치·부족 정보·구현 기능·정상/실패/취소 시험을 작성했다.
- 시험 ID는 `T-RQ-nnn-N/F/C`이며 360개가 고유하다. 시험 내용은 설계이고 상태는 전부 `NOT_RUN`이다.
- `source_ids`는 통합 바인딩을 위해 의도적으로 비워 두었다. `source_hints`의 USER_INSTRUCTION과 문서명은 이미 읽은 요구 근거의 단서이며 미확보 원본이 실제 읽힌 것처럼 표시하지 않았다.
- `source_locator`는 실제 읽은 계획/지시/감사/사진 위치 또는 통합 담당에게 받은 공식 URL이다. 파서 내부·원본 archive member·영상 타임코드가 미확인인 행에 경로를 만들어 쓰지 않았다. 그 칸은 `missing_information`과 실제 source 카탈로그 연결에서 보완한다.
- `confirmed_information`은 `USER_REQUIREMENT` 또는 사진/감사/통합 담당의 읽기 범위를 밝히고 나머지는 `UNKNOWN`이다. 요구를 확정했다고 역사적 세부 규칙이 확정되는 것은 아니다.
- `fact_status`는 전부 `UNKNOWN`으로 보수적으로 유지했다. 기본 기능 요구는 확정됐지만 대부분의 개별 한국 역사값은 아직 확정되지 않았고 하나의 행이 여러 필드를 포함한다. 통합 담당은 필드별 근거를 검토해 필요한 행만 판정을 조정할 수 있다.
- `use_status=ACQUIRED`는 이 초안의 읽은 요구 문서/사진 상태다. 원본 자산의 해독·의미 식별·게임 실행 참조·실행 완료를 의미하지 않는다. 최종 sources 연결 시 개별 게임 원본의 상태는 sources와 issues에서 별도로 관리한다. 새 게임 `BOUND/EXERCISED`는 0이다.
- `planned_phase`는 기능의 향후 구현/검증 단계이며 P2 이상이 지금 승인되었다는 뜻이 아니다. P2 원본·두 플랫폼 위험 검증, P3 종단 동선, P4 일괄 자료, P5 시스템, P6 동기화·업데이트, P7 통합 검증을 유지한다.

## 통합 담당에게 남기는 점검

1. 각 행의 source_ids에 현재 실제 확보/읽은 sources 레코드를 연결하되 요구 근거와 역사 사실 근거를 구분한다.
2. 한국 클라이언트 원본 내부 멤버·ID를 확인한 결과가 있으면 해당 요구의 source_locator/confirmed_information을 구체화한다. 다른 시대/NA 데이터로 메운 부분은 대응 후보로 남긴다.
3. 미식별·해독 실패·버전 불일치·지원 코드 없음·패키지/캐시 결함·의도적 미사용을 issues에 연결한다. 자료가 없는 기능은 구현 기능과 독립 확인 시험을 삭제하지 않는다.
4. 최종 요구 파일의 ID·출처 참조·필수 범주·해시와 정상/실패/취소 칸 누락 검사를 수행한다.
5. 기존 보관 원본·사진·세이브·비밀키를 공개 저장소에 넣지 않는다. 이 초안은 그 파일의 실제 바이트를 포함하지 않는다.

## 초안 정적 검사

실제 CSV 재읽기로 120행, 요구 ID 120개 고유, 시험 ID 360개 고유, 빈 필수 시험/구현/부족정보 0, 범주 9개, 시험 `NOT_RUN` 120행, 게임 실행 이용 상태 BOUND/EXERCISED 0행을 확인했다. source_ids 최종 바인딩 검사는 통합 단계 대기다. 이 검사는 CSV 구조 검사이며 게임 시험 PASS가 아니다.
