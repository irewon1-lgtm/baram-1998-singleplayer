# 한국 1.25 지도 — 보유 자료 소비 확대

`tools/rebuild/p2/priority_maps.py`는 기존 `kr125_map.py`의 원본 근거·24px 타일·OTB·충돌 판정을 재사용한다. KR1.25 ZIP과 고정 DAT/PAL reader의 SHA256을 확인하고 새 비공개 출력 세대에 변환한다. 기존 GEN003 지도·원본 ZIP·추출 파일은 수정하지 않았다. 정적 원본 EXE 구간 검사만 재사용했으며 원본 EXE 실행은 하지 않았다.

196/198은 전체 원작 지도 복원율이 아니다. 분모 218은 확보한 KR1.25의 MAP 파일 수이며, 해당 파일이 1998~2001 특정 도시·사냥터라는 역사적 확인은 별도다. 250은 지도 250개가 아니라 198개 파일에 들어 있는 독립 저장 청크 수다. 원작 바이트·팔레트·객체 ID는 이 자료판본의 `ORIGINAL_VERIFIED`이나 목표시기 정체성은 `UNKNOWN`이다. 재구성 도시명이나 출구를 추가하지 않았다.

MAP0은 정확한 64×64 청크 49개, MAP208은 5개다. 원본 정적 코드에서 디스크 청크 크기만 확인된다. 서버가 지정한 활성 폭·높이와 청크의 세계 배치가 없으므로 제곱수라는 이유로 MAP0을 7×7 지도로 연결하지 않았다. 각 청크는 `inspection_id=kr125:map-0:chunk-0`처럼 원본 MAP ID와 저장 순번을 보존한다. 검수 경계 밖 이동은 차단하며 교차 청크 이동·성문 왕복은 구현 PASS가 아니다.

## 원본 높이0 기록의 처리

MAP0의 OTB154·217·825·826, MAP158의1449·1457, MAP267의1920·1924는 원본 OTB에 실제 높이0으로 기록돼 있다. 이는 인덱스가 없는 그림과 다르다. 변환기는 `nonvisual_native_objects`에 native ID·좌표·높이0·원본 충돌 마스크를 보존하고 **아무 raster도 생성하지 않는다**. drawable 객체 목록에 빈 PNG·frame0을 삽입하지 않았다. 총 23개 배치는 audit와 각 비공개 chunk JSON으로 추적된다.

## 검증과 재현

`MAP_AUDIT.json`은 전체 218개 원본의 해시·정확한 길이·상태·격리 이유, 독립 청크 생성 수, 실제 음성시험을 보관한다. 단일 청크 자르기·추가 바이트·부분 다중 청크·빈 입력·알 수 없는 객체·알 수 없는 지형을 거부하며, 정확한 다중 청크에서도 세계 폭/배치는 null로 남기는 시험을 실행했다. GEN003 MAP1·99·100의 바닥/합성 PNG 바이트와 객체·지형·충돌 mask는 새 출력과 직접 비교한다. 실행 결과 수치는 audit의 checks를 따른다.

```sh
python3 tools/rebuild/p2/priority_maps.py \
  --client-zip PRIVATE/sources/KR_1.25_winbaram.zip \
  --reader PRIVATE/parser/legacy_assets.py \
  --output PRIVATE/maps-priority-v2 \
  --baseline-maps PRIVATE/GEN003/maps \
  --audit docs/rebuild/priority-fill/MAP_AUDIT.json
```

출력은 기존 경로가 있으면 중단하여 과거 변환 세대를 덮어쓰지 않는다. 공개 Git에는 변환 코드·비민감 진단 메타만 남기고 원본·변환 그림·지도 JSON은 비공개로 인계한다. 실제 검수 앱 연결·화면·이동 증거는 통합 보고의 `RUNTIME_EVIDENCE.json`을 따르며 Android/Windows/Galaxy PASS로 확대하지 않는다.

## v1 PNG 출력 실패와 v2 수정

통합 담당자의 전수 PNG 구조검사에서 첫 완성 출력 `maps-priority`의 PNG 1,620개 중 4개가 실패했고 변환 자산 조립이 중단됐다. 해시·크기 일치는 PNG 디코딩 유효성 검사를 대신하지 못한다. 독립 재검사에서도 MAP0/chunk15·20·29와 MAP226의 floor PNG가 동일하게 실패했다. `MAP_V1_PNG_FAILURES.json`에 정확한 출력 SHA256·길이·PNG chunk 진단을 보존한다. 각 파일은 IDAT의 65,536바이트 payload 직후 CRC 앞에서 끝나 이후 PNG 데이터·IEND도 없다. 이것은 출력 파일 절단이 관측된 것이며, Pillow/파일 직접쓰기/환경 중 어떤 계층이 원인인지는 확정하지 않았다. 원본 클라이언트의 손상으로 판정하지 않는다.

v1 출력과 실패 기록은 보존하고 새 `maps-priority-v2`를 생성했다. PNG는 먼저 BytesIO에서 완전히 인코딩하고 구조·CRC 및 재개방한 실제 픽셀의 원본 이미지와 일치를 검사한다. 그 바이트를 같은 디렉터리의 임시 파일에 쓰고 flush/fsync·바이트 재조회한 뒤 atomic replace하며, 교체 후 바이트·PNG.verify·재개방 픽셀 디코딩을 확인한다. 생성 완료 후 PNG **전수**를 다시 PNG.verify와 실제 디코딩으로 검사한다. 공통 타일 규칙·이미지·원본 ID·출구·보행 판정 조건을 완화하지 않았다. 최종 v2의 전수 PNG 수·판정과 기존 3지도 회귀 결과는 `MAP_AUDIT.json.generation_checks`에 있다. v1의 실패를 해소로 덮어쓰지 않는다.
