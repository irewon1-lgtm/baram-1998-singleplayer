# 한국 2001 작업용 규칙 선정·검수

`KR_GUIDE_2001_WORKING_PROVISIONAL`은 1998~2001 복원 범위 안에서 P2 검수에 쓸 작업용 프로필이다. 2001년 아카이브 자료를 선택했다는 뜻이며, 클라이언트 빌드·전체 서버 규칙·원작 전체의 역사적 정답이 확정됐다는 뜻은 아니다. 원본 P1.5, Work B001/B002, GEN003 데이터와 미선택 기본 프로필은 수정하지 않았다.

## 실제 선정

- 공식 자료 248행: 기술 학습 188, NPC 서비스 22, 시설 규칙 13, 제작 사실 7, 성장·이동·생성 등 18. 긴 원문·전체 표는 공개하지 않고 비공개 JSON의 포인터와 원본 ID·해시를 `RULE_SELECTIONS.jsonl`에 연결했다.
- Work B002의 같은 프로필 유도 관계 70행: 몬스터 설명의 제한된 의미 24, 상점 상품 ID 관계 42, 직업별 스승·학습 재료 관계 4. 이 연결은 `RECONSTRUCTED`이며 원본값 확정으로 세지 않는다. 상점 가격·AI 수치·재료 소비 거래를 구현한 것이 아니다.
- 참고 아이템 41행은 관계의 참조 폐쇄를 위한 원본 행이다. 활성 아이템 추가·정가 확정으로 세지 않는다. 실제 구매·판매 가격은 모두 null이다.
- `RULE_SELECTIONS.jsonl`의 333행은 318개 원본/유도 관계 선정과 **중복되는** 충돌 필드 15개를 포함한다. 고유 콘텐츠 333개 완료가 아니다.

## 15와 82의 정확한 차이

기존 `official_independent_review.json.cross_era_conflicts`의 15건은 두 시대에 명시값이 있는 **직업 기술 금전·재료 필드**의 독립 검수 부분집합이다. `CONFLICTS_RESOLVED.csv`에서 각 2001 후보 하나를 선택했으며 2000 대안과 원문 위치를 보존했다. 역사적 진실까지 해결했다는 표시는 false다.

`research_official_core.json.epoch_conflicts`의 더 넓은 모집단은 82건이다: 지역명 46, 재료 14, 경험치 11, 드롭 가능 아이템명 9, 학습 금전 2. 15건 밖에 있는 unknown→known 학습 재료 한 건도 포함된다. 이 82건은 비공개 오버레이 `supplemental_epoch_differences`에 **전부 그대로** 남겼다. 15건을 전체 충돌 수로 축소해 보고하면 안 된다.

같은 2001 공식 HTML 안의 진마반지 가격 250,000전/25,000전은 판본 선택만으로 해결되지 않는다. `WSD-GE-8a0dac694cd421ec`, `KRO-ITEM-fc2e3568a13a64`, `KRO-ITEM-f4f3fa56f4e52c`는 `CONFLICT_UNSELECTED`를 유지한다. 추후 동일 시대 NPC 거래 캡처나 다른 당시 원문으로 매입/판매·오기 여부를 구별해야 한다. 평균·자리수 보정·첫 행 선택은 적용하지 않았다.

전체 Work 159후보 처리는 SELECTED 70 / 다른 판본 보존 58 / 참고 28 / 같은 판본 가격 충돌 1 / 제작 NPC 위치 가설 2다. 위치 가설은 시설이 같다는 이유만으로 제작 NPC를 확정하지 않았다. NA 154 참조 실패는 이 작업에서 지우거나 한국값으로 채우지 않았다.

## 소비 계약과 실제 시험

`priority_rules.py`는 고정 SHA의 P1.5 ZIP·B001/B002 ZIP, 각 내장 manifest, 정규화 원문 행·기존값 해시를 검사한다. 출력은 별도 비공개 파일이며 기존 입력을 덮어쓰지 않는다. 평민 Lv1/공격 기술 없음/Lv5 전직은 명시된 사용자 요구를 보존한 제품 규칙이며 새로운 역사적 근거로 주장하지 않는다.

`rebuild/p2/content/priority_rules.gd`가 실제 JSON을 읽는다. 기술 ID별 직업·레벨을 검사하고 NPC ID별 서비스·판매 후보·매입 전용 후보를 구별한다. 같은 캡처에서 명시된 상점 재고 별칭만 연결한다. 길드의 좌표는 참고점이며 NPC 실내 타일로 배치하지 않는다. 직업·레벨을 충족해도 학습·전직 거래는 `BLOCKED`, `eligible=false`, `transaction_enabled=false`다. `job_level_eligible=true`는 해당 두 조건이 맞는다는 뜻만 가진다. 재료·돈·효과·타격·저장 기능 전체가 작동한다는 뜻은 아니다.

실제 실행 결과:

- 고정 입력 데이터의 Python 계약·참조 검사 16건 PASS.
- 실제 선정 데이터 복사본을 변형한 잘못된 프로필·중복 기술 ID·충돌값 변경·P3 거래 활성화·진마반지 조용한 선택, 실제 core ZIP 1바이트 변조 등 음성시험 6건에서 모두 거부를 확인했다. 원본은 그대로 보존했다.
- Godot 4.6.3 Linux headless에서 `test_priority_rules.gd`를 실제 실행했다. 188개 기술과 22개 NPC를 모두 소비하여 직업·레벨 거부, 올바른 조건에서도 거래 차단, 평민 초기값, 4직업 Lv4/Lv5 경계, 상점 재고 차이·명시 별칭·매입 전용, 알 수 없는 ID·누락 파일 차단, 입력 불변 17건 PASS.
- 위 시험은 **읽기 전용 규칙 소비 시험**이다. 화면 시각 검수, 실제 사냥·학습·경제 거래, Windows·Android·갤럭시 실행 PASS를 의미하지 않는다. 통합 검수 UI 결과는 작업 전체 `RUNTIME_EVIDENCE.json`에서 별도로 기록한다.

재현 도구는 `tools/rebuild/p2/priority_rules.py`, `tools/rebuild/p2/test_priority_rules.gd`다. 비공개 `priority_rules.json`·`godot-validation.json`·`negative-validation.json`의 SHA와 전달 위치는 전체 작업의 생성 세대 manifest를 사용한다.

## 남은 구체적 공백

- 직업 기술 원본 ID↔효과↔소리↔명중·재행동 시점, 실제 학습/실패/자원 차감: 원본 규칙 자료와 P3 시스템 구현 필요.
- 진마반지 같은 판본 가격 충돌과 다른 아이템의 명시 가격 열→실제 NPC 매입/판매 가격 의미: 당시 거래 화면/공략 필요.
- 토끼고기 등 재료·상품의 안정 ID가 없는 관계: 이름만으로 임의 아이템 생성하지 않음. 동일 시대 공식 표·서버/패킷 식별 근거 또는 재구성 별도 승인 계약 필요.
- NPC 22개 문서 행의 개별 외형·실내 위치·대화 분기: 공통 외형 일괄 부여하지 않음. 이름 묶음은 별칭인지 여러 개체인지도 보존.
- 제작 7개 사실의 불명확 금전·확률·실패 손실·일부 재료 수량·NPC: 문서의 부분 사실을 완성 레시피로 실행하지 않음.
- 성장 교환 구간 경계·표의 오기, 이동 목적지 MAP ID: 원문 구간 문자열·unknown을 보존하며 실측 또는 명시적 재구성 계약 필요.
