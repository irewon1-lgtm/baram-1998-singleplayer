# G1 자료 선택·콘텐츠 계약

정본: `BARAM_REBUILD_V2_RESOURCE_FIRST_20261016` / B2. 기계 정본은 같은 폴더의 `G1_CONTRACT.json`, 재현 도구는 `tools/rebuild/v2/generation_contract.py`다. 이 계약의 등록 수량은 게임 실행·완료 수량이 아니다.

## 실제로 읽은 인벤토리

P1.5 인계의 `docs/rebuild/p1_5/selected_content/` 전체 35개 파일, 44,796개 레코드의 실제 바이트를 읽어 공개 catalog의 SHA-256·행수와 대조했다. 여기에는 저장 참고 계약 8개가 포함된다. 원본은 수정하지 않았다. JSONL·자산 프레임·효과 필드를 각각 독립 게임 콘텐츠로 더하지 않는다. 파일별 해시·레코드 수·선정 용도는 JSON의 `inventory`에 있다.

|---|---:|---|

| 한국 공식 아이템 | 771 | 2001 477행 + 고유 2000 7행, 같은 이름의 다른 수치도 ID 보존 |

원본 지도 이미지 2개는 같은 고구려 지도 계열의 서로 다른 크기다. 129개 지도/시설 첨부 링크도 각각 별개로 완성된 지형이 아니다. 원본 지도 파일·청크·이미지 수로 새 플레이 지도 분모를 부풀리지 않는다. G1은 보존한 기본 11지도와 선정 몬스터의 32지역을 연결하는 재구성 지도를 사용하며, B4의 결정적 지도 생성 후 실제 지도 ID 전부를 `--freeze-derived`로 동결한다.

현행 공개 후보도 한 번 넓게 대조했다. [넥슨 공식 직업·기술 가이드](https://baram.nexon.com/Guide/Contents/01-02)의 HTML과 실제 본문 이미지(4,906,011바이트, 1130×6956)를 받아 전체 및 직업 설명/기술 UI 확대 부분을 읽었다. 이미지 하단 갱신일은 2026-04-07이다. 전사의 근접 전방 역할, 도적의 은신·순간 타격, 주술사의 원거리 공격, 도사의 회복 지원을 확인했다. 최신판의 11직업·9단계 승급과 높은 레벨의 예시는 G1의 4직업·1~99에 그대로 적용하지 않는다. 기존 자료로 현재 세대를 설계할 수 있어 최신 수치나 새 콘텐츠 ID는 채택하지 않았다. 최신 전체 기술표·지도·자산을 확보했다는 뜻은 아니다. 실제 이미지 해시와 접근 결과는 JSON의 `public_source_crosscheck`에 남겼다. 첫 웹 이미지 조회가 실패한 기록과 별도 방식의 실제 바이트 확보를 구분했다.

## 동결한 콘텐츠

| 종류 | 선정 원본 ID | 보존한 런타임 보조 ID | 현재 필수 ID 수 |
|---|---:|---:|---:|
| 몬스터 | 346 | 0 | 346 |
| 기술 | 190 | 0 | 190 |
| 아이템 | 484 | 3 | 487 |
| NPC | 22 | 2 | 24 |
| 제작/조합 | 9 | 0 | 9 |
| 지도 | 원본 이미지와 일대일 대응하지 않음 | 11 | 11 + 명시적 생성 지도 |

위 표의 단위는 필수 안정 ID다. 몬스터 346개 원본 ID 중 13개는 선택 값까지 같은 중복 행이므로 완전히 같은 의미를 합친 분모는 333이다. 별도 지역·동작 변형의 중복 여부까지 추정해 더 합치지는 않았다. `exact_semantic_source_counts`와 alias 표를 함께 보고하며, 346을 고유 몬스터 종류의 확정 수로 표현하지 않는다.

190기술은 기존 2001 188개를 모두 보존하고, 공백 제거 후 이름·직업·신수가 2001에 없는 2000 기술 2개를 더한 것이다. 전사·도적·주술사·도사의 기본/공통 166개와 선정 승급 기술 24개다. 검객/검제/검황, 자객/진검/귀검, 술사/현사/현인/현자, 도인/명인/진인의 기본 직업과 승급 단계를 JSON에 명시했다. 배우는 레벨이 99라는 이유만으로 승급 조건을 지우지 않는다. 고유 기능은 동일 피해/회복으로 일괄 치환하지 않는다.

이전 `P4_HANDOFF`의 유보 기술 178 ID와 미배치 NPC 15 ID가 이번 필수 집합에 모두 포함되는 것도 실제로 확인했다. 생성 도구는 하나라도 누락되면 원장 생성을 실패시킨다. 이 포함 검사는 실제 행동 완료 판정과 구분한다.

선택 규칙은 다음과 같다.

1. 2001 한국 자료를 현재 수치 기본값으로 사용한다. 같은 정규화 이름·종류·직업·신수의 2000 자료는 버전 변형으로 보존한다. 수치를 합하거나 평균 내지 않는다.
2. 2001에 없는 2000 고유 콘텐츠는 추가한다. 몬스터 15, 기술 2, 아이템 7 ID다. 시대 완전 일치를 목표로 자료를 버리지 않는다.
3. 같은 이름이어도 선택한 값이 다르면 서로 다른 ID를 유지한다. 이름을 키로 만든 dict로 아이템 50개 변형이나 지역별 몬스터를 조용히 덮어쓰지 않는다.
4. 선택 값·직업·신수·이름까지 모두 같은 몬스터 13쌍은 `exact_semantic_aliases`에 명시했다. 별도 런타임 ID로 둘 수도 있고 안정 ID alias로 합칠 수도 있다. alias를 쓰면 옛 ID를 해석할 수 있어야 한다.
5. `범형제` 등 묶음 머리행은 이미 분리된 구성 몬스터 외에 추가 몬스터로 만들지 않는다. 2000의 `망또00번~21번`·`웨딩드레스1~11번` 두 범위 행도 2001의 개별 22+11개 아이템이 모두 있어 추가 구매 아이템으로 만들지 않는다. `grouped_source_bindings`에 원본 행 ID와 모든 구성 ID를 남겼다. 최초 선택 도구가 이 범위 행을 고유 아이템으로 계산한 결함은 구성원 대조 후 수정했다. 닫혀 있다고 명시된 우체국·복권상점은 활성 서비스로 만들지 않는다. 옛 온라인 휴면/운영 정책은 개인 저장 삭제 규칙으로 가져오지 않는다.
6. 골무·깨끗한얼음 제작의 역사적 실행 조건이 미확정인 것은 미구현 사유가 아니다. G1 제작 명세에는 포함하되 결과·재료·비용·실패 소비를 명시한 재구성으로 구현한다. 이를 원작 확정 조합법이라고 보고하지 않는다.

각 원본 의미 행의 선정/제외 ID·이유·자료 지문은 `source_dispositions`에 있다. 기존 공개/비공개 catalog를 읽은 것과 실제 원본 레코드를 읽은 것을 구분했다. 이번 원장 생성에서는 실제 35개 파일을 검증했다.

시설·성장·운송의 31개 규칙 ID도 따로 관리한다. 29개는 구현 또는 명시적 재구성의 런타임 참조가 필요하다. 무한장 PvP와 혼례의 다른 플레이어/배우자 기능 2개는 개인용 오프라인 범위에 맞지 않아 `OFFLINE_REFERENCE_EXCLUDED`로 명시했다. 해당 NPC의 대사·주제 퀘스트를 별도로 재구성할 수 있지만 PvP·배우자 이동을 구현했다고 보고하지 않는다. 코드 감사는 31개의 처리 기록과 29개의 구현/변환 참조를 콘텐츠 등록 수와 별도로 집계한다.

## 실행·획득·저장 계약

게임 등록은 다음 정상 경로와 행동이 있어야 연결 완료다.

| 종류 | 필수 연결 |
|---|---|
| 지도 | 시작점에서 정상 출구로 도달, 양방향/의도한 귀환, 유효한 입구·충돌·NPC·스폰 좌표 |
| 몬스터 | 도달 가능한 지도 스폰, 이동/대응/타격/죽음·전리품·재생성, 지역/단계에 맞는 수치 |
| 아이템 | 상점 구매·몬스터 드롭·퀘스트·제작 중 정상 획득, 종류에 맞는 착용·소모·재료 사용 |
| NPC | 지도 배치·접근 가능한 인접칸, 대화·해당 역할 서비스, 역할별 재고 |
| 기술 | 직업·신수·레벨·승급·비용·재료 조건, 정상 교사, 고유 대상·행동·소모·효과·종료 |
| 제작/퀘스트 | 재료 자체의 정상 획득, 중복/실패/취소의 원자적 거래, 결과 사용, 저장 후 재시도 |
| 성장 | 네 직업 1~99의 일관된 경험치·체력/마력·경제, 선정 승급과 후속 기술 연결 |

동일 아이템을 자기 자신을 재료로 제작할 수 있다는 등록만으로 정상 획득했다고 보지 않는다. 떨어지지 않는 드롭(확률 0)도 획득 경로가 아니다. 아이템이 모두 같은 공통 상인에만 놓이는 방식으로 역할별 상점 요구를 지우지 않는다. 북미 규칙이나 추론 수치를 적용하면 해당 필드의 근거 단계·환산식을 남긴다.

공통 실행기 허용 기술 행동: `damage`, `heal`, `buff`, `debuff`, `status`, `return`, `shrine`, `identify`, `restore_mp`, `summon`, `cleanse`, `revive`, `loot`, `blink`. 전달 방식은 `melee/projectile/area`, 상태는 `stealth/paralysis/poison/slow/silence/protection/haste/blindness`다. 그 밖의 명령은 변환 오류로 잡는다. 아이템은 기본 착용/HP·MP/재료 행동 및 명시적 `return/cleanse`를 사용한다. 허용 이름이 있다는 것만으로 효과가 실행됐다고 인정하지 않는다.

저장은 기존 `gp:*`·`KRO-*` 안정 ID를 유지한다. 새 지도는 새 ID를 사용하고 기본 11지도 치수·충돌/출구를 무단 변경하지 않는다. 지도 버전 변경 시 원본 저장 사본·좌표 변환·검증·실패 복구가 필요하다. 원래 저장 위치를 임의 입구로 덮어쓰지 않는다. 네트워크 계정 순차 이어하기·실제 Windows/Android/Galaxy 검증은 별도 게이트로 유지한다.

## 재현 및 검증 범위

`python tools/rebuild/v2/generation_contract.py --self-test`는 선택·중복·범위 행 이중계산·끊어진 참조·획득 불가·순환 alias·자기 재료 제작·지원하지 않는 행동·필수 ID 보존·반복 동결의 동일성을 다루는 14개 결정적 assertion을 실행했다. 여기에는 실제 실행기가 지원하는 실명 상태 허용과 미지원 임의 상태 거부가 포함된다. 결과는 PASS이며 검사 도구와 fixture에만 적용된다. 게임을 실행한 시험은 0건이다.

실제 경로를 넘겨 `--normalized … --catalog docs/rebuild/p1_5/selected_content/catalog.json --baseline …/gameplay_content.json --output docs/rebuild/v2/G1_CONTRACT.json`으로 원장을 재생성할 수 있다. catalog만 있고 실제 레코드가 없거나 해시/행수가 다르면 실패한다.

결정적 콘텐츠 변환 후 `--contract docs/rebuild/v2/G1_CONTRACT.json --freeze-derived …/gameplay_content.json --output …`로 새 지도·필수 보조 ID를 추가 동결한다. 기존 필수 원본 ID는 삭제하지 않는다. 같은 원장의 `--audit-runtime`은 ID·정적 참조·지도 연결·선언한 정상 획득을 검사하며 결과를 `STATIC_PASS/STATIC_FAIL`로 한정한다. 행동·화면·실기기 완료는 실제 런타임 시험과 플랫폼 증거가 있어야 한다.

B2의 원본 ID 집합과 최종 r2의 지도·보조 ID를 모두 동결했다. 최종 계약은 지도 76, 아이템 593, 몬스터 원본/안정 ID 346(정확히 같은 의미의 중복을 합치면 333), 기술 190, NPC 24, 퀘스트 52, 제작 9, 승급 13, 수련 규칙 7 ID다. 최초 소스 집합에 지도 65와 아이템 보조 106, 명시적 퀘스트·승급·수련 의존성을 추가했고 원본 필수 ID를 삭제하지 않았다.

최종 r2 콘텐츠에 대한 독립 정적 감사는 `STATIC_PASS`였다. 모든 필수 ID·참조, 지도 76/76의 실제 셀 단위 출구 도달, 선언한 정상 획득, 허용 행동을 확인했다. 원본 규칙은 29개 구현/변환 참조와 2개 오프라인 제외 사유를 구분했다. 이 도구의 실제 게임 행동/플랫폼 시험은 여전히 `NOT_RUN`이다. 런타임 행동·화면·기기 검증은 통합 담당의 해당 증거를 별도로 사용한다. B4는 필수 ID 미연결을 `CODE_FAIL`로 남기고 해결해야 하며, 이 계약의 수량을 줄여 검사만 통과시키지 않는다.

확보한 효과 자산도 연결했다. `effect_assets.py`는 기존 한국 가이드 이미지와 원본 효과의 완전한 RGB 대응이 확인된 48개 기술에 고유 원본 효과를 적용했다. 선택한 원본 효과 ID는 13개이고, 기존 효과를 합친 런타임은 18개다. 실제 PNG 135개의 원본/복사 해시를 검사했다. 나머지 142기술은 대응 실패를 숨기지 않고 재구성 효과를 명시했다. 원본 효과의 위치·실제 타격 시점·지연 단위·음향 대응까지 확인됐다는 뜻은 아니다. 이름/직업 격리·모호한 대응·경로 탈출을 포함한 효과 선택 도구의 7개 검사가 PASS했다.

r3에서는 G1 ID 집합을 그대로 유지하고 원본 근거에 맞춰 실명/회복 및 체력 소비 기술 값을 보정했다. 실행기가 지원하는 `blindness`가 정적 감사 허용표에 누락돼 발생한 `SKILL_STATUS_UNSUPPORTED` 1건은 감사 도구의 결함이었다. 허용표와 양성·음성 fixture를 수정한 뒤 같은 r3를 다시 감사해 `STATIC_PASS`를 확인했다. G1 계약 JSON이나 이미 빌드된 r3 입력 지문은 재생성하지 않았다. 이전 감사 도구 지문을 사용해 생성된 콘텐츠의 이력도 유지한다.
