## 4. 기존 FAIL을 숨기지 않되 무관한 P2까지 막지 마라

G0 결과를 전송·바이트·정규화 무결성·참조 연결·역사적 의미로 나눠라.
알려진 북미 참조 154건의 구성과 실제 ID·원인을 대조하라.
기술→직업115, 스폰→몬스터24, 드롭→아이템8, 드롭→몬스터7이 이전 기록이다.
숫자만 같다고 같은 실패가 재현됐다고 하지 마라.

고정 원천의 FAIL·import exit 1·의미 BLOCKED를 그대로 보존한다.
원본 행 삭제·NULL 대체·기본 직업 부여·검사 완화로 PASS를 만들지 마라.
후속 변환의 수정은 근거·ID 대응·적용 범위·새 버전으로 별도 기록한다.
원래 실패가 예상대로 나오는 회귀시험 PASS와 데이터 자체의 FAIL은 다른 결과다.

전체 G0가 BLOCKED/FAIL인 경우에도 독립 P2 단위를 시험하려면,
그 단위에 필요한 입력과 모든 참조 대상을 먼저 고정·전수 검증하라.
빠진 입력·북미 오류에 의존하지 않는다는 검사 결과와 영향 목록이 있어야 한다.
그 단위의 G0만 통과했다고 보고하고 전체 G0를 PASS로 바꾸지 마라.
단위 필수 입력이 빠졌거나 의존성이 불명확하면 해당 단위는 중단한다.

이것은 시험 범위 분리이지 필수 데이터 누락의 면제가 아니다.
자료 손상·미지원 동작을 정상값으로 바꾸어 실행하지 마라.
한 도시·한 기술·인증환경이 막혀도 무관한 단위는 계속 검증하라.


## 5. P2를 위한 하나의 작은 검수 프로젝트를 만들어라

기존 게임의 main.gd를 통째로 가져오거나 전체 게임을 다시 생성하지 마라.

재사용한 모듈은 새 입력·호출부·플랫폼에서 실제 다시 확인한다.

한국 맵, 캐릭터 합성, 효과·음향, 생성·입력·저장 시험을
하나의 작은 검수 프로젝트와 공통 모듈로 구성하라.

입력/UI, 상태·규칙, 렌더링, 저장·동기화는 분리한다.
이 모듈들은 나중에 새 게임에서도 사용할 수 있어야 한다.

Godot은 우선 후보이지 정확한 버전이 확정된 것은 아니다.
같은 작은 장면의 Windows·Android 빌드/실행으로
엔진·언어·플러그인·내보내기 버전을 결정·고정하라.
최신이라는 이유로 시험 중 버전을 바꾸지 마라.

2000/2001 충돌은 시험별 명시 프로필로 분리하라.
한 번의 시험 안에서 같은 필드의 다른 시대 값을 혼합하지 마라.
기본 프로필 선택은 근거와 영향이 있는 제안으로 남기고
공통 MASTER_PLAN이나 P1.5 원장의 null을 임의로 바꾸지 마라.

play() 호출·파일 디코딩·오디오 신호 출력·실기기 청취는 별도 판정이다.

## 8. 활용 경로·캐시·판정 체계를 고정하라

자료별로 원본→해독→식별→채택→코드 소비→실제 화면/소리/상태→시험을 연결하라.
미활용은 손상·미식별·미지원 코드·패키징 누락·다른 시대·의도적 미사용으로 나눠라.
찾은 파일 수가 아니라 실제 읽고 표시하고 실행한 범위를 보고하라.
모든 자료를 시험 APK에 억지로 넣을 필요는 없다.

실행 manifest와 캐시는 입력 파일·파서·변환 코드·설정·프로필·스키마·
타일/팔레트 대응의 지문을 포함한다.
변환 코드만 바뀌어도 필요한 캐시가 무효화되는 시험을 수행하라.
필수 맵·효과·소리·아이콘 누락을 continue·기본값으로 숨기지 마라.

시험마다 환경·코드SHA·입력manifest해시·도구/엔진버전·명령·기대값의 근거,
실제 출력·종료코드·화면/영상/음향·실패 이유를 남겨라.
검수 코드가 만든 값을 같은 코드로 재검사한 것만으로 원작 일치를 주장하지 마라.

기술 동작 PASS, 원작 일치 판정, 플랫폼 실행 판정을 분리하라.
자료 미확정은 미확정으로, 실행 안 한 것은 NOT_RUN으로 남긴다.
초기 실패 후 수정한 경우 전후 근거와 최종 입력에서 재시험한 결과를 보존하라.
대표 성공을 전체 지역·NPC·기술·기기에 일반화하지 마라.


## 9. 안전·비용·결과 전달 경계

참고 프로그램은 출처·해시·의존성을 확인한 사본만 제한된 환경에서 실행하라.
무작정 받은 EXE·설치 스크립트·SQL·Lua를 사용자 PC나 운영 환경에서 실행하지 마라.
로컬 시험 서버는 필요한 로컬 인터페이스만 열고 외부에 공개하지 마라.
압축·파서에는 경로·크기·깊이·CPU·메모리·시간 한도를 적용하라.

타인 계정자료·토큰·비밀번호·서명키·사용자 세이브는 출력하거나 게시하지 마라.
시험 DB는 필요한 콘텐츠 allowlist와 신규 합성 계정으로 만든다.
민감 참고 원본은 감사용 비공개 캐시와 실행 입력을 분리한다.
폰트 파일은 인계 자료에 포함하지 마라. 검수 환경에서는 적절한 시스템 글꼴 등을 사용하라.
해시·정적 검사 PASS를 악성코드 부재 보증으로 확대하지 마라.

무료 범위를 확인할 수 없는 작업은 비용 없는 경로를 우선 찾고
불확실하면 해당 실행만 중단·보고하라. 유료 전환·새 결제·운영 배포는 하지 마라.

코드·비민감 결과는 Codex 브랜치에 저장하고 원격 재조회로 확인한다.
원본과 원본이 포함된 시험 빌드·시청각 증거는 기존 비공개 보관 원칙을 따른다.
P2 시험용 EXE/APK는 실제 제작·검증한 범위와 독립 설치 방법을 명시하라.
완성 게임이라고 부르거나 사용자 기존 앱 위에 설치하도록 안내하지 마라.

파일 전달은 실제 접근 가능한 비공개 artifact·기존 전달 경로로 확인하라.
/workspace/...만 제시하고 다운로드 완료라고 하지 마라.
전달 수단이 없으면 실제 생성 위치·해시·전달 BLOCKED를 기록하라.
확인되지 않은 링크·Library ID·업로드 성공을 만들어내지 마라.
