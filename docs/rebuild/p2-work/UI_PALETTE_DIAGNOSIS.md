# KR491 생성 배경 팔레트 결함 정정

GEN002의 DLGNEW02는 구조 해독에 성공했으나 잘못 연결한 `DlgLogin.pal` 때문에 심한 색상 노이즈가 났다. 이를 정상 해독 화면으로 제시할 수 없다. GEN002와 그 실제 플랫폼 실행 증거는 그대로 보존한다.

독립 근거는 KR491 원본 `Winbaram.exe`의 정적 코드다. 원본 실행 파일 SHA-256은 `f88846f2d3ce394d8dcc6e55288b8977ff3d34e160a4029337bdaccee84475ea`이다.

- `0x44649a..0x4464ad`: `DLGNEW02.EPF` 생성자 호출은 마지막 팔레트 인수에 NULL을 전달한다.
- `0x419727..0x419748`: 생성자는 NULL 팔레트 인수를 원본 문자열 `BARAM.PAL`로 바꾼다. 문자열의 가상 주소는 `0x4e7414`이다.
- `0x4197fd..0x41980f`: 그리기 경로는 이 생성자 필드에서 팔레트를 조회한다.

따라서 `Baram.pal` 바인딩은 테두리 외관을 보고 한 추론과 구분된다. `Title.pal`도 유사하게 보이지만 색상 23개가 다르므로 원본 호출 근거에 따라 `Baram.pal`을 사용한다. 압축·암호화 변경 없이 같은 EPF 픽셀과 마스크로 성별·나라·신수 선택 그림이 정상 표시됐다. 원작 생성 흐름, 실제 선택 입력, 목표 연도 일치 여부는 이 정정으로 검증되지 않는다.

`tools/rebuild/p2/correct_kr491_ui_palette.py`는 고정 원본 DAT·EXE·reader 지문과 원본 코드 위치를 먼저 대조한 뒤 새 비공개 출력 디렉터리를 만든다. 기존 GEN002에 쓰지 않는다. 새 PNG 한 장과 실행 manifest의 해당 UI 바인딩, 추가 소비 팔레트 및 정정 이력만 바꾼다. 원래 PNG도 새 출력에 보존한다. 전체 EPF 해독을 반복하지 않고 부모 출력과 파일별 차이, 2,100개 PNG 형식, 해당 UI의 동일 치수·동일 alpha를 확인했다. 정정본의 실제 Godot/Windows/Android 실행은 별도 기록을 따른다.

기존 DLGLOGIN·DLGNEW01·DLGPASS 마스크 3건은 계속 BLOCKED다. 각 행은 프레임 폭보다 2픽셀 길며 각 파일의 7개 행에서는 불투명 run도 프레임 오른쪽을 넘는다. 원본 그리기 코드에는 표시 영역을 제한하는 로직이 있지만, 그 사실만으로 원본 마스크 불일치의 원인이 확정되지는 않는다. 행을 자르거나 FF를 임의로 126으로 바꾸는 수정은 적용하지 않았다.

지문·변경 범위·확인 결과는 `UI_PALETTE_DIAGNOSIS.json`에 기록했다. 실제 원본·디코딩 PNG·원본 코드 전체 disassembly는 비공개 경로에만 둔다.
