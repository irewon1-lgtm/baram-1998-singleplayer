## 0. 이번 실행의 목적과 담당 전환

자료를 Codex로 계속 운반하는 방식 대신, 이미 만들어진 Codex 코드를 자료에 접근할 수 있는 Work 환경으로 가져온다. 원본·코드·시험·결과 전달을 한 담당이 소유하도록 전환한다.

이번 작업은 자료 조사만 하는 Work 작업이 아니다. 다음 범위를 수행한다.

- 기존 Codex P2 코드·결과를 보존하여 인수한다.
- 현재 Work 실행환경에서 실제 비공개 입력 접근과 필요한 자료 연결을 검증한다.
- 원본 기반 P2-01~03을 최우선으로 구현·실행·비교한다.
- 연결된 생성/UI/저장과 Windows·Android 시험을 수행하고, 가능한 인증 시험의 조건도 확인한다.
- 코드·자료 지문·실행 증거·재개 가능한 비공개 입력 경로를 함께 남긴다.

이 지시문을 사용자에게서 받은 이번 Work 실행에 한해 과거의 ‘Work는 자료만 담당/P2 코드·기준본 실행·시험 빌드 금지’ 범위를 위 범위로 변경한다. 과거 조사·시험·권한 기록은 수정하지 않는다. 자료 증분 작업과 P2 통합 작업을 같은 작업으로 위장하지 않는다.

Codex에는 같은 범위의 신규 실행을 병렬로 맡기지 않는 운영 방식이다. 다른 세션이나 프로세스를 실제로 중지했다고 가정하지 않는다. 최신 원격 상태와 작업 기록을 읽고, 다른 담당이 움직이더라도 그 브랜치·파일·작업 디렉터리를 건드리지 않는다.

이번 종료점은 G0·P2 실제 결과와 다음 P3 착수 판단이다. P3 플레이 시험판/P4 대량 콘텐츠 구축/운영 배포로 자동 진입하지 않는다. 향후 담당은 기본적으로 Work를 유지하되, 변경이 필요하면 코드·원본·빌드·결과에 대한 수신 환경의 실제 접근과 실행 재현이 먼저 입증되어야 한다. ‘P2가 끝났으니 Codex’라는 자동 전환은 금지한다.

## 4. 첫 실행: 실제 입력과 지속 접근 경로 확인

### 4.1 사용자에게 대용량 파일 재전달부터 요구하지 않는다

현재 마운트, 이전 Work 작업 사본, 연결된 Project/Library와 기존 비공개 원본 위치를 먼저 확인한다. 과거 세션의 /workspace·/mnt/data 경로가 새 세션에도 있다고 가정하지 않는다. Library ID도 실제 바이트가 아니다.

필요한 기본 입력:
- BARAM_P1_5_handoff_20261016.zip (core version1)
- BARAM_P1_5_reference_sources.zip.part001~003
- BARAM_WORK_SOURCE_DELTA_B001_20261016.zip
- BARAM_WORK_SOURCE_DELTA_B002_20261016.zip
- INPUT_MANIFEST의 원본42개와 해당 P2 단위가 참조하는 실제 중첩 바이트.

이미 확보된 전송용 통합 ZIP이나 분리 ZIP이 보이면 원래 파일별 SHA로 대조해 재사용한다. 또 다른 대형 묶음을 만드는 것이 기본 작업이 되어서는 안 된다. 핵심 한국 클라이언트·아틀라스·효과·WAV부터 실제 파일 경로와 필수 참조를 연결한다.

현재 문서 작성 환경에서는 인계·증분6파일과 핵심 원본5파일의 SHA/길이를 대조했다. 이 사실은 다음 Work 환경의 접근 성공, 원본42개 전수검증, 포맷 해독·게임 실행 PASS가 아니다.

### 4.2 전체 G0와 단위별 G0를 분리한다

고정 영수증·도구의 실제 CLI와 지문을 사용해 원래 전달본·manifest·정규화 자료를 검사한다. 2,489-ID 이전 원장용 경로표와 3,565-ID import용 경로표를 섞지 않는다. 이 수량은 기존 세대의 값이며 신규 세대에서는 정확한 선언 집합을 별도로 기록한다.

정규화 데이터44,796행·원본42개 전체를 현재 환경에서 확인하지 않았으면 전체 G0는 BLOCKED/NOT_RUN으로 유지한다. 누락 입력을 required 집합에서 지워 PASS로 만들지 않는다.

동시에, 특정 P2 단위의 입력과 그 입력이 재귀적으로 참조하는 모든 자료가 실제 바이트·형식·해시·관계까지 확인됐다면 그 단위의 G0를 별도로 판정하고 진행할 수 있다. 옛 감사 문서나 사용하지 않는 북미 자료가 없다는 이유만으로 독립적인 한국 맵·캐릭터·효과 시험을 모두 멈추지 않는다. 의존 범위를 증명하지 못했거나 단위 필수 원본이 빠지면 그 단위는 중단한다.

북미 참조 FAIL154건과 기존 import 종료코드는 원천 결과로 보존한다. 예상 실패 재현이라는 테스트 PASS와 실제 데이터 PASS는 별개다. 필요한 참고 경로는 원인·영향·변환 근거를 기록해 별도 계층에서 처리하고, 행 삭제·NULL·기본 직업으로 숨기지 않는다.

민감 RTK 참고2파일은 이미 확보한 캐시가 있으면 지문을 재확인하고 감사 목적으로만 사용한다. 새 환경에 없다면 필요한 범위를 분리한다. 과거 G0 전수 재현에 필요하다고 해서 외국 서버의 계정정보를 실행 DB·시험 앱·인계 묶음에 넣지 않는다.

### 4.3 중단 후에도 되살릴 수 있게 한다

각 입력에 지속 파일ID 또는 검증된 비공개 저장 위치, 버전, 길이, SHA, 필요한 parser·config·schema 지문과 복원 명령을 남긴다. 현재 임시 경로만 적고 보존 완료라고 하지 않는다.

기존 비공개 저장소 후보 irewon1-lgtm/baram-windows-private는 문서 작성 시 private 메타데이터와 루트 목록을 확인했다. 기존 분할 런타임이 있다고 최신 P1.5/Work 입력이 모두 있다는 뜻은 아니다. 실제 파일별 해시와 경로를 대조한다. 기존 원본·서명키·설치본을 덮어쓰지 않고, 이미 허용된 비공개 보관/전달 기능과 무료 범위를 확인해서만 사용한다. 새 공개 업로드나 인증이 없는 다운로드 링크로 우회하지 않는다.

검증된 원본은 재다운로드·재해독하지 않고 캐시를 재사용하되 지문이 달라졌으면 영향 범위를 다시 검사한다. 실제로 접근할 수 없는 것만 정확한 ID·오류·필요 단위로 보고한다. ‘접근 안 됨’ 조사만 반복하며 합성시험 건수를 계속 늘리지 않는다.

## 5. 이번 핵심 산출: 실제 원본을 소비하는 P2-01~03

공통 Godot 검수 프로젝트를 그대로 확장한다. 현재 4.6.3/GDScript는 인수한 시험 후보이며 최신이라는 이유로 버전을 교체하지 않는다. 버전 변경이 필요하면 원인과 두 플랫폼 영향을 먼저 남긴다.

### P2-01 — 한국 지도

- 확보된 실제 한국 MAP·타일·정적 객체를 그린다. 출처 클라이언트/맵ID/프레임/팔레트와 소비 코드를 연결한다.
- 한국1.25 맵 해독 성공과 목표시기 국내성·부여성의 일치는 별도 판정이다. 실제 타일 렌더 성공을 먼저 확보하되 역사적 동일성으로 확대하지 않는다.
- 공식 전체그림의 신국내성/다른 판본 가능성과 Work 증분의 시대 제약을 적용한다. 보관일이2001년이라는 이유만으로 일반 국내성 지형에 채택하지 않는다.
- 사대문·주요 건물·초보 사냥터 입구를 앵커로 원점·격자·치수·좌표 후보를 대조하고, 충돌·가림·출구 왕복을 실제 시험한다. PCX 픽셀을 격자로 간주하지 않는다.
- 비영사천문·귀환은 검증된 지역/도시/방향/조건별 목적지로 처리한다. village 고정, 임의 가장자리, 입구 주변 편의 포털로 원작 이동을 대체하지 않는다.
- 손상 부여ZIP은 별도 보존한다. 대체본이 없으면 확보 근거로 제한한 재구성 후보와 미확정 영역을 표시하고 원본 지도라고 보고하지 않는다.

## 9. 결과·비공개 보존·실제 전달

이번 핵심은 코드뿐 아니라 다음 실행에서 필요한 자산도 다시 열 수 있는 상태다.

2. 한국 지도·캐릭터·효과/음향이 실제로 화면과 동작에 연결됐는가? 확인한 범위는?
3. 기존 Codex 성과 중 무엇을 그대로 재사용했고 무엇을 왜 바꿨는가?
4. 전체 G0/단위 G0, P2-01~06, Windows/Android/Galaxy/IME/인증의 정확한 상태는?
5. 사용자가 볼 실제 화면·영상·시험 앱은 어디에 있으며 수신 가능성을 확인했는가?
6. 다음 Work 실행에서 코드와 필요한 원본을 함께 복원할 수 있는가?
7. P3에서 처음~사냥~저장으로 이어지는 작은 플레이 구간을 만들 준비가 됐는가?

‘자료 전달 준비’나 합성시험 건수 증가만으로 완료하지 않는다. 원본을 소비하는 실제 P2 진전과 남은 차이가 결과다. P3 판단은 지도·합성·효과/음향·생성·저장 등의 필수 기반이 입증됐는지에 따라 READY/PARTIAL/BLOCKED로 제시하고, 사용자의 다음 실행 지시 전에는 P3/P4를 시작하지 않는다.
