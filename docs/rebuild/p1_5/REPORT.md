## 검증·감사 결함·보안

필수 입력 전체와 실제 읽은 집합을 비교하는 검증기로 바꿨다. 전체 정적 바이트 gate는 **2,489 expected/read/matched, 누락0**으로 PASS다. 이것은 포맷 전부 해독·고증·게임 기능 PASS가 아니다. 정상/0입력/필수1개누락/바이트변조/잘린ZIP/HTML위장/JSON·CSV오류/중복ID/끊어진참조/버전·파서·설정·코드지문 오류 등 격리25회귀를 실제 수행했다. BLOCKED/FAIL/NOT_RUN과 scoped/global 결과·종료코드가 구분된다.

정규화 importer는 선언된 전체 파일 집합·해시·행수, 실제 원문/CSV/SQL/프레임·팔레트·WAV, 프로필, 부모/ID참조와 미지원 의미를 읽는다. **정상 데이터 무결성, 원천 참고본의 끊어진 참조, 한국 게임 의미 준비도를 별도 판정**한다. 알려진 source graph 오류를 통과시키기 위해 원천 데이터를 고치거나 NULL로 숨기지 않았다. 최종 실제 실행은 37물리파일·44,796고유행·출처 바이트1,241건을 읽어 무결성 PASS, 원천 참조 FAIL, 한국 의미 준비 BLOCKED, 종료코드1이었다. 원천 미해결154간선은 P1998 스폰→몬스터24, RTK 드롭→몬스터7/아이템8, 기술→직업115개다. RTK에서 소비 코드로 확인한 동적 드롭 풀5키만 별도로 구분했다. importer의 격리18회귀도 PASS했다. 정확한 명령·입력 지문·종료코드는 `VALIDATION.json` 및 `import_validation.json`을 따른다. 초기 실패 결과도 `import_validation_initial.json`에 보존했다.

공식 핵심928행은 다른 DOM 파서로 전체 대조했고, 기술 설명377행/180고유설명도 독립 검토했다. 실제 발견한 주석 처리 행 유입·금전/재료 오인·HTML 닫힘 누락·효과/대상 오분류를 최소 수정하고 재검증했다. 전수인 표/프레임 비교와 화면4건/미리보기13개 같은 제한된 시각 범위를 구분한다. 새 게임 소리 출력·동작 시점은 관찰하지 않았다.

정적 해제는 고정 reader의 import 전 SHA검사·깊이/크기/경로제어·캐시 재검사를 적용했다. RTK 원시 SQL의 계정/해시/IP/저장내용과 기본암호 설정, 임시 전송 토큰을 발견해 공개/인계 대상에서 제외했다. 값 출력·키회전·계정시험·원본삭제는 없었다. 상세 범위·남은 native parser/휴리스틱 한계는 `SECURITY.md`에 둔다. 해시일치나 패턴0건을 악성코드 부재로 보고하지 않는다.

## 저장과 다음 시작점

공개 Git에는 문서·메타데이터·정적 도구만, 비공개 인계 파일에는 선정 값과 민감 파일을 제거한 참고 소스·검수 증거를 둔다. 원본42개는 기존 지속 ID를 재사용한다. reference source ZIP의 해시·제외·11,428파일 확인은 INPUT_MANIFEST와 `reference_package_validation.json`에 있다.

자기 참조를 피하려고 최종 커밋/원격 tree 재조회, 완성 ZIP의 SHA/지속 파일ID·가져오기 절차는 별도 `DELIVERY_RECEIPT.json`에 기록한다. Work의 독립 사본3,037개와 전체경로표3,564 ID를 사용한 깨끗한 디렉터리 검사에서 기존 원장2,489 PASS 및 전체44,796행 무결성 PASS/참조154 FAIL이 재현됐다. 초기 경로표 범위 혼합과 composite101 ID 누락은 실제 발견·수정·재시험했고 이전 원장 검증기의 거부를 완화하지 않았다. 이는 Codex 수신 환경 G0 PASS가 아니다. 이후 별도 P2 지시가 있으면 최신 STATE→이 REPORT→NEXT_P2_DELTA의 G0에서 시작한다. 입력/파서/설정/범위 지문이 같은 기존 검사는 반복하지 않는다.

인계 최종화에서 최신 원격 체크포인트를 보존하고 경로 복원 도구와 CLI/지문 계약을 일치시켰다. 원문 HTML·첨부와 이전 도구 판본은 비공개 묶음의 PRIVATE_SOURCE_INDEX에서 실제 SHA로 복구하며 원본42개·민감 SQL은 별도 접근한다. 전체 파일명·길이·SHA 및 정규화 catalog를 검사하는 격리20회귀와 새 패키지/깨끗한 디렉터리 검사 결과는 외부 DELIVERY_RECHECK_RECEIPT.json을 따른다. 기존 clean_handoff_validation.json은 이전 도구 세대의 유효한 과거 증거로 보존한다.

재개 후에는 새 입력 복원기3565ID/3038고유해시와 실제 CLI·지문에 맞춰 인계 계약을 수정했다. 누락돼 있던 깨끗한 사본의 필수 바이트검사2489/2489 PASS 및 가져오기44796행 무결성PASS·참조154 FAIL/exit1을 실행했다. 기존 조사와25/18/20회귀는 동일 도구·입력·범위의 유효한 증거를 재사용했다. 이번 실행 근거는 `resumed_static_recheck_summary.json`, 현재 전달본/지속ID·버전·해시는 `DELIVERY_RECHECK_RECEIPT.json`을 따른다.
