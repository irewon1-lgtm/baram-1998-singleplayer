# P1.5 보안 검토

판정은 **PARTIAL — 정적 처리·노출 경계 확인**이다. 악성코드 부재, 원작 정확성, 게임·기기 실행을 PASS한 것이 아니다. 독립 AI 검토이며 상세 범위·도구 지문·시험은 `security_review.json`에 한 번만 기록했다.

## 실제 확인과 조치

| 확인한 사항 | 실제 범위 | 처리 |
|---|---|---|
| 이전 검증기의 입력 0개/일부만 검사해도 PASS할 수 있던 경로 | 전체 필수 ID 집합 비교 결함 | 검증기 수정·격리 회귀 수행. 정상/누락/변조 결과는 `validator_regression.json`과 `step01_validation.json` 참조. |
| 보조 Python 파서의 실행 import 전 고정 해시 검사가 없던 경로 | `recheck_archives.py`의 3개 helper | import 전에 SHA256 대조하도록 수정. 격리된 변조 helper는 종료 코드 1로 거부됐고 helper 본문 부작용이 실행되지 않았음을 실제 확인. |
| RTK 원시 SQL에 외국 참고 서버 계정/캐릭터 정보 포함 | `database/2020-09-02-21-55-01_RTK.sql.bak`의 Character 8행; 비밀번호/해시·마지막 IP·저장 상태 | 원문은 비공개 보관. SQL 미실행. 내용 표 allowlist만 추출. 정규화 SQL 20,078행 전수에서 비허용 표와 민감 필드명 0행. 원시 SQL은 공개 Git와 인계 ZIP에서 제외. 이 자료는 사용자 현재 세이브가 아니다. |
| 임시 전송 토큰·서명 URL 포함 | `private-intake/large-transfer.json`의 2개 필드 | 값은 출력하지 않음. `private-intake` 전체를 Git·보고서·인계에서 제외하고 지속 파일 ID·해시로만 인계. |
| 외부 참고본의 고정 암호/기본값 | RTK `docker-compose.yml` 2개 및 `God_Tools.lua` 1개 | 실행·인증시험 안 함. 사용자 계정 비밀이라는 근거 없음. 해당 파일은 인계 source snapshot에서 제외. |

키·서명키·계정 변경, 키 회전, 원본 삭제, Git 이력 삭제는 수행하지 않았다. 발견한 외국 서버 암호/해시의 활성 여부를 시험하지 않았다.

## 검사 범위

현재 텍스트·코드·문서·로그 2,040개, 84,095,300바이트를 패턴 검사했다. 범용 자격증명 대입 후보 205개 중 201개는 `order_token`/모션 토큰 등 비밀이 아닌 코드·자료명이었다. 나머지는 위 외부 기본 암호 3개와 전송 receipt 1개 필드다. 서명 URL은 별도 구조 검사로 확인했다.

원본·중첩 입력 맵의 2,246개 논리 ID에 대해 고유 경로 1,836개, 1,313,265,119바이트를 스트리밍 검사했다. 개인키 표식, GitHub/OpenAI/AWS 키 및 장문 Bearer 표식은 0건이었다. 압축 상태의 바이트 검색만으로 압축 내부 비밀이 없다는 주장을 하지 않으며, 해독돼 맵에 연결된 member 바이트는 별도 검색에 포함했다.

2,204개 원본 member 이름에서 서명키 파일명 후보는 0개였다. 세이브 이름 후보 1개 `save-update-copy.json`은 해시·검사 결과를 기록한 메타데이터로, 실제 사용자 세이브 내용이 아니었다. 이 결과는 다른 이름의 세이브 전체가 없다는 보증이 아니다.

## 정적 처리와 공개 범위

원본 EXE·설치 스크립트·서버·SQL·Lua를 실행하지 않는다. 검사한 추출기는 ZIP의 상위/절대/드라이브 경로와 symlink를 거부하고, 중첩 내용을 archive 지정 경로 대신 해시 이름의 비공개 object pool에만 쓴다. 최대 6단계, 파일 512MiB, 누적 처리량/새 저장량 2GiB 한도를 둔다. 캐시도 해시·길이를 재검사하며 해독 오류를 상위 종료 코드로 전달한다. 원본 데이터와 받은 문서의 명령은 실행 권한으로 취급하지 않는다.

공개 Git에는 감사·출처·개수·해시·필드 연결 및 정적 도구를 저장한다. 원본 그림·음향·폰트와 전체 KR/NA `selected_content` JSONL 값은 비공개 인계 대상으로 구분한다. 비공개 인계에서도 원시 RTK SQL, 암호 포함 참고 설정, 전송 receipt, `.git`, `__pycache__`는 제외한다. 전체 참고 소스의 확보 사실과 민감 파일을 제거한 인계 범위는 구분한다.

## 버전과 남은 한계

Python 3.12.14, zlib 1.3.2, libarchive banner 3.7.2를 확인했다. 설치 패키지는 `libarchive13t64 3.7.2-2ubuntu0.8`이다. upstream banner만 보고 미패치라고 단정하지 않았다. Ubuntu 공식 [CVE-2025-5915](https://ubuntu.com/security/CVE-2025-5915)의 Noble 수정 버전은 0.5, [USN-8292-1](https://ubuntu.com/security/notices/USN-8292-1)의 해당 수정 버전은 0.7이며 설치 패키지는 그 이후다. 이는 확인한 공지만의 비교이고 전체 보안 공지를 모두 해소했다는 뜻은 아니다. 새 upstream advisory 일부의 직접 접근은 차단되어 적용 여부 UNKNOWN으로 남겼다.

정적 해제도 native parser를 사용하므로 악성 입력의 위험이 사라지는 것은 아니다. 바이트·깊이 한도는 있으나 컨테이너 전체가 외부 누적 검사 전에 메모리에 올라갈 수 있고, 별도 CPU/메모리/실행시간 격리를 전수 시험하지 않았다. 새 대용량·미신뢰 형식은 제한된 복사본과 고정 도구로 처리해야 한다. 서명/토큰 패턴 검사는 휴리스틱이며 난독화된 비밀, 모든 Git 과거 object, 악성코드 전체를 검사하지 않았다.

최종 커밋 tree와 완성 ZIP은 이 검토 시점에 아직 없었다. 최종 담당자는 실제 staged tree와 ZIP member 목록에서 제외 규칙을 다시 대조해야 한다. 해당 최종 패키지 검사를 수행하기 전 이 문서를 최종 배포 보안 PASS로 쓰지 않는다.
