# 구현 운영 계획: 누가, 언제, 무엇을 검증하나

> 실행 전 기획 문서. 실제 개발 작업·사양 검증 PASS 아님.

## 역할과 책임

**사용자 (Project Owner)**: 1998 특정 시기의 기억 확인, '원작 엄격/싱글 보조' 선택, 기능과 비용 승인, 실제 PC에서 게임 체험 검증. 서버 설정·코드 작성은 기본적으로 요구하지 않는다.

**ChatGPT/Work (Historian / Producer)**: 1998 잡지·업데이트 기록·원본 사이트 수집과 출처 분류, 사료의 독립성/모순 검토, 우선순위·PR 승인 기준, 연구 원장 업데이트. 검색만 하고 판정하지 못한 항목은 BLOCKED.

**Codex (Developer)**: Godot 4 2D 윈도우 네이티브 프로젝트, 맵 렌더링, 충돌, 조작, 몬스터 AI, 전투/경험치/인벤토리, 저장·불러오기, 스킬/직업/승급 상태 머신, 자동 테스트와 빌드. 증거 없는 구현 수치는 `assumed`로만 작성.

**아트·오디오 담당 (제작 혹은 허가 확인)**: 신규 픽셀 그래픽/효과음 제작 또는 명시적 이용 허가 확인, 원작 UI를 재현하기 위한 규격 조사. 수익형 리소스 API는 사전 승인.

**품질 검증 담당 (테스트 자동화 + 사용자)**: 원작 스크린샷/동영상/매뉴얼과 자체 게임의 재현성 검증. 테스트 실제 실행 로그 없는 PASS 금지.

## Stage 0: 사료 고정과 권한 구분

- 연구 파일 해시 보존, 1998-12 적용일/버전 증거 조사.
- 넥슨 IP 허가·원본 스프라이트/사운드 정책 결정.
- 1998 화면 1개라도 버전/시점/사용 권리가 확인될 때까지 그래픽의 '동일' 판정 금지.
- **통과:** 원장 중복/참조검사 PASS + 유효 스냅샷 범위 승인. 원본 수치 확보 없으면 수치 고증은 BLOCKED.

## Stage 1: 초보 구간 '한 화면' 버티컬 슬라이스

- Godot 4, 로컬 저장, 재접속 후 동일 상태 복원 (서버/클라우드/로그인 없음).
- 임시 자체 제작 타일맵 하나, 이동·막힘·NPC 상호작용, 몬스터 2~3종, 피격/드롭·인벤토리, 레벨업·세이브 로드.
- 다람쥐/토끼/말은 원작 출현 여부 확인 전까지 *플레이 테스트용 이름 후보*.
- `strict_1998.json` 미확정 수치는 비워두고 `assumed_dev.json`로만 샌드박스 실행.
- **통과:** Windows에서 실게임 실행 + 결정적 시뮬레이션 + 리그레션 자동화 + 사용자 조작 검사. 원작 일치 PASS와 별개.

## Stage 2: 레벨 1~30 확대

- 1998 당대 적용이 확정된 마을/초급사냥터→포탈 연결, 직업 선택/마법/상점/드롭, 경험치·죽음/부활.
- 4개 직업의 기능이 코드로 작동하고 대표 플레이 경로가 끝까지 진행되는지 검증.
- **통과:** 모험 루프 및 승급 규칙 입력 테스트 PASS. 원작 증거 누락은 별도 BLOCKED.

## Stage 3: 레벨 31~99

- 당시 입증된 전지역·던전/NPC, 몬스터 AI, 장비, 직업별 기술·경제·레벨 성장 전부 확대.
- 설정 파일만 바꿔 미확정 수치가 후일 검증값으로 교체되도록 코드와 데이터 분리.
- **통과:** 4직업 레벨 99 완주 및 저장/불러오기/수치 테스트. 원작 정확성은 소스별 계측 결과로만 판단.

## Stage 4: 1차 승급과 싱글 지원

- 당시 정확한 체력·마력/아이템/퀘스트가 확인되면 승급 조건 고증 구현.
- 원작 멀티 유저 협동 조건은 별도 `SOLO_ASSIST` 보조 규칙 옵션으로 분리.
- **통과:** 4직업 1차 승급 루프 실행. 1998 승급 원본 수치 미확보 시 역사적 동일 PASS 불가.

## Stage 5: 최종 원작 비교/리스크

- 화면 UI 픽셀 경계 비교(판본 검증된 원본 한정), 캐릭터 이동/전투 타이밍, XP/HP/MP/드롭의 원본 수치·통계 비교, 전체 마을·사냥터/직업 체크리스트.
- 각 항목 `PASS/FAIL/BLOCKED/UNVERIFIED`. 재현율은 검증 가능한 분모, 테스트 실행 로그 및 별도 아트/수치/동작 축으로만 표시.
- **통과:** 사용자 승인 + 기능 CLEAN PASS. 역사적 동등성은 해당 항목에 원본 증거가 있을 때만 PASS.

## 기술 선택 / 안전

- 게임: Godot 4.x (GDScript, 타일맵·씬, 자동 테스트), Windows 오프라인 실행파일. 라이선스: https://godotengine.org/license/.
- 원본·추정·시험 데이터는 각 파일·버전·경로로 분리, 임시 테이블을 원본 테이블에 덮어쓰기 금지.
- 별도 서비스/서버/실시간 동기화/회원가입/계정 복구는 MVP 범위 밖.
- 처음부터 전체 맵/모든 몬스터 생성 금지: 단 1개 화면 + 사냥·레벨업 게임 루프를 직접 검증한 뒤 확장.
- 실시간 AI NPC, 유료 AI 호출은 원본과 맞지 않을 수 있으므로 초기 구현에서 제외.

## 시간 추정 (보증 아님)

- 검증용 초기 플레이 구간: 전담 1인 기준 수 주 단위.
- 1~99와 승급까지 폭넓은 구현: 수개월 이상. 원작 수치/권리 확보가 장기 병목 가능.
- 원본 동작·아트가 확보되지 않으면 '100% 동일' 완료 시점은 예측 불가능.

## 절대 하지 말 것

- 1998 자료가 없는 값을 확정값으로 채우지 말 것.
- 제작·저장·실행하지 않고 '완료/배포/PASS' 기록 금지.
- 본 프로젝트의 PR을 기존 BCT/병원앱 저장소에 생성하지 말 것.
- 저장소는 사용자 요청에 따라 Public으로 운영. 게임 완제품 외부 배포 및 무단 원작 파일 커밋은 별도 판단.
