# 개인용 오프라인 게임 실행과 검증 범위

공개 체크아웃에는 원본·추출·파생 그래픽, WAV, 외부 무라이선스 서버 코드를 넣지 않는다.
원본은 `/workspace/baram-private`와 개인용 결과 ZIP에 보존한다.

현재 독립 Godot 실행 경로를 선택했다. 확보된 한국 4.91 그림을 실제 엔진에서 표시하고,
오프라인 입력·전투·거래·저장을 실행할 수 있다. 기존 Godot 실행 환경, DAT/EPF/PAL
해독기와 화면 시험 방식을 재사용한다. 원본 Windows 클라이언트와 Project1998의
실제 화면 호환성은 이 Linux 환경에서 실행하지 못했다. Project1998의 미확인 라이선스
코드·CSV를 새 게임에 복사하지 않았다. 이 제한을 호환 성공으로 기록하지 않는다.

```bash
cd /workspace/baram-1998-singleplayer
XDG_DATA_HOME=/workspace/baram-private/setup/data \
XDG_CONFIG_HOME=/workspace/baram-private/setup/config \
XDG_CACHE_HOME=/workspace/baram-private/setup/cache \
godot --path game -- --assets=/workspace/baram-private/game-assets
```

그래픽 화면이 있는 Linux에서 실행한다. 클라우드에서는 `tests/run_playable_screen.py`가
자신의 비공개 X11 화면을 열어 실행한다. 이 시험은 실제 Godot 입력 이벤트와 뷰포트,
독립적인 X11 화면 캡처를 사용한다. 물리 키보드를 사람이 조작한 시험은 아니다.

화살표/WASD 이동, Space 공격, Enter/F NPC 대화, G/쉼표 줍기, I 물품,
E 장착, U 물품 사용, 1~3 기술, Tab 대상 선택, F5 저장, F6 복구를 지원한다.
Shift+화살표 제자리 방향 전환은 게임 완성을 위한 추가 조작이며 원작 확인값이 아니다.
Esc로 대화창을 닫거나 저장 후 일시 정지하고, 정지 화면에서 Q로 종료한다.

상점은 ↑↓ 선택, B 구매, V 판매, R 장착 무기 수리, C 토끼고기 요리를 제공한다.
주막에서 H는 휴식이다. 수련원에서 Enter로 기술을 배우고, 배운 기술을 1~3에 지정한다.
재실행하면 체크섬이 유효한 저장을 읽고, 손상되면 이전 백업을 읽는다.

이전 8개 제작 맵을 소스에 보존하고, 현재 개인 패키지는 원본 북미 4.95 지도 38개와
한국 4.91/북미 4.95가 바이트까지 같은 타일·팔레트·객체를 사용한다. 한국 1998 마을의
동일 복원으로 주장하지 않는다. 마을·원본 주막·대장간·네 직업 수련원·쥐굴·뱀굴·곰굴·
감옥·토끼굴·원본 상점과 실내가 연결된다. 캐릭터의 4방향·걷기·공격·시전·줍기,
원본 혼령, 토끼·다람쥐와 다른 몬스터/NPC 그림을 쓴다. 몸/머리/무기의 발 기준 좌표와
원본 그리기 순서를 보존한다. 무기 피해는 공격 시작 후 160ms에 적용하고 600ms 간격을
사용한다. 이 시간값과 미확인 그림·효과음의 역할 연결은 교체 가능한 제작 추정이다.

원본 숫자 자료는 그대로 유지했다. 같은 게임 계산 모듈에서 37개 정의를 실행하고,
실패한 저장 정수 처리만 수정하여 영향 받은 성장 시험을 재실행했다. 1~30 성장과
경제 시뮬레이션, 98→99 경험치 경계는 실제 화면 완주와 구분한다. 아직 연결되지 않은
상위 미확정 기술의 효과는 미완료로 남는다. 레벨 1~30 네 직업 기술 66개와 공통 기술
3종을 자원·대상·효과·상태·동작에 연결했고, 부족한 효과는 추론/오프라인 보완으로
구분한다. 모든 기술의 역사적 동일성, 원작 타이밍·31~99 전체 지역·승급과
전체 여정 완주는 별도의 미완료 항목이다.

`dev/codex-asset-intake-20261014` 최신 커밋 `80d3da1`의 상세 기준서와 필수 인계 파일을
끝까지 읽고 현재 개발 계보에 병합했다. 초기에 관측한 GitHub 403은 이후 실제 push/fetch가
성공하여 해결되었다. `dev/codex-asset-runtime-20261014`로 저장하고 원격 SHA를 재조회한다.
main과 조사 브랜치는 병합하지 않는다.

전체 타일은 60개 페이지 연락시트에 연결된다. 개인 자료 폴더의 `review/index.html` 또는
`review/A-00.png` 등으로 모든 ID를 찾아볼 수 있다. 전체 페이지 자동 생성은 직접 시각
검토와 다르다. 기존 6페이지에 이어 남은 54페이지를 실제로 보아 첨부 14,835프레임의
연락시트 검토를 마쳤다. 의미·원본 색상이 미확정인 그림까지 판독 완료로 바꾸지는 않는다.
추가 원본 타일 35,269개는 별도 원장에 등록했다. source/group/palette/index 정규 ID,
미활용 해결 시도와 실제 결과는 기존 원장/`unused-resolution-current.json`에 연결했다.
원본 맵 전체 좌표 원장은 공개 복사를 막기 위해 개인 패키지의
`private_assets/source_maps/asset-use-locations.jsonl`에 넣는다. 이전 공개 좌표 원장은
우리 제작 배치의 과거 증거다. 두 원장의 적용 버전을 섞지 않는다.

이전 149개는 8개 제작 맵에 배치한 **서로 다른 타일 ID**였고, 배치 횟수는 9,223회였다.
138개는 당시 실제 카메라 경로에서 그려진 서로 다른 ID다. 나머지 11개는
`A:246`, `A:472~477`, `C:172~175`로, 실내 경계·카펫·상단 벽이 해당 경로에 보이지 않았다.
등록·배치·실제 표시의 차이를 해독 실패로 처리하지 않았다.

현재 옷은 I/E로 착용하고 방어 계산·몸 그림을 함께 바꾼다. K에서 배운 기술을 1~3에
지정한다. 길잡이는 넓은 원본 마을과 지역을 이동하게 한다. 새 상점의 취급 물품은
포목·푸줏간·장비 등의 역할에 맞춰 다르게 연결했다. 공통 비영사천문·성황령·물품감정,
동작 중 저장 대기, 원본 몬스터 공격 프레임, 독 피해·해독과 빛의 시야 효과도 연결했다.
NPC 역할·진입 좌표 일부·시야/변신/상위 미확정 공격량은 제작용 보완이다.

네 직업 레벨 30 상태를 **계산으로 준비한 별도 저장**에서 기술 학습·장착·시전·전투를
실제 창으로 시험했다. 이 결과는 네 직업을 1에서 30까지 키운 완주 증거가 아니다.
그 fixture에는 `validation_fixture`가 표시된다. 실제 이전 레벨 5 저장을 이어 키운
시험은 별도 `natural-progress` 기록으로만 집계한다. 원작 유사도 퍼센트를 만들지 않는다.
# 확보 자료 활용 확대 실행 기준 (2026-10-14 후속)

출발 코드 `afe0252`와 원격 최신 SHA가 같음을 실제 `git ls-remote`로 확인했다.
원본 타일 14,835개와 기존 프레임 1,137개 검사 결과는 동일 입력 해시 기준으로
재사용한다. 이번 결과와 예전 PASS 범위를 혼합하지 않는다.

이번 적용 묶음의 실행 전 기준:

1. 원본 맵: 헤더 없는 4바이트 셀, 별도 치수, TBL 기준 번호, 타일별 팔레트,
   SObj의 세로 조각·충돌을 원본 바이트와 대조한다. 모든 참조 범위가 유효해야
   변환 PASS이며, 실제 화면·진입·보행·출구는 별도 게임 시험을 거친다.
2. 자산 검토: 기존 검토 6페이지를 재사용하고 남은 54페이지를 직접 본 범위만
   기록한다. 페이지 검토와 개별 조각 의미 확정, 원본 화상 동일성은 별개다.
3. 게임 연결: 원본 실내·마을·사냥터를 기존 엔진에 연결하고 NPC·전투·보상·
   출입구를 실제 입력으로 수행한다. 이동 불가·미연결 출입구를 발견하면 수정한다.
4. 동작·착용·기술: 새 연결을 실제 재생하고 MP/HP·피해·상태·장비 화면 변화를
   확인한다. 원작 미확인 동작·수치는 대체/제작값 표시를 유지한다.
5. 저장: 실제 플레이의 상태를 저장한 후 새 프로세스에서 복구해야 PASS다.
   기존 사용자 저장 파일을 시험용 파일로 덮어쓰지 않는다.
6. 보존: 원본·추출·파생 그림·원본 맵과 포함 캡처는 비공개 ZIP에 보존한다.
   코드·자체 레시피·집계·오류 증거만 개발 브랜치에 저장하고 원격 SHA를 확인한다.

전체 원작 동일성, 네 직업 레벨 30 완주, 31~99·승급의 미실행 상태를 위의
부분 성공으로 바꾸지 않는다. 미활용 자산은 정확한 ID와 실제 해결 시도에 연결한다.
